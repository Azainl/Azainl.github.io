## P0　必修（附修复方案）

### 1. 代码高亮主题配置完全失效 —— 目前渲染的是 Shiki 默认主题

**这是最严重的一个，而且构建不会报错。**

`astro.config.mjs` 里写的是：

```js
shikiConfig: {
  theme: { light: 'github-light', dark: 'github-dark' },  // ❌
}
```

Astro 的双主题配置项是 **`themes`（复数）**，不是 `theme`。查 `node_modules/astro/dist/types/public/config.d.ts:1429` 官方注释确认：

```js
theme: 'dracula',              // 单主题
themes: { light: 'github-light', dark: 'github-dark' },   // 双主题
defaultColor: false,           // 关掉默认的 CSS 变量输出
```

传了对象给 `theme`，Shiki 无法识别，静默回退到默认主题。构建产物实证（`dist/posts/blog-build-notes/index.html`）：

```html
<pre class="astro-code" style="background-color:#1e1e1e;color:#bbbbbb; ...">
```

`#1e1e1e` 是 VS Code Dark Plus（Shiki 默认），不是你配的 `github-dark`（`#24292e`）。后果：

- 浅色模式下代码块是一个突兀的深色块
- 主题切换对代码块完全无效（内联样式优先级最高，`.prose pre { background: var(--code-bg) }` 被覆盖）
- 你那篇《Astro 静态博客的几处构建优化》里讲的按需图标、字体子集都落地了，唯独高亮没生效

**修复**（两步，缺一不可）：

```js
// astro.config.mjs
markdown: {
  shikiConfig: {
    themes: { light: 'github-light', dark: 'github-dark' },
    defaultColor: false,   // 不加这句，Shiki 会输出 @media (prefers-color-scheme: dark)，
    wrap: true,            // 而你的主题是 .dark 类切换的，两者对不上
  },
},
```

```css
/* global.css —— 用 .dark 类而不是媒体查询来切换 */
.astro-code, .astro-code span {
  color: var(--shiki-light);
  background-color: var(--shiki-light-bg);
  font-style: var(--shiki-light-font-style);
  font-weight: var(--shiki-light-font-weight);
}
.dark .astro-code, .dark .astro-code span {
  color: var(--shiki-dark);
  background-color: var(--shiki-dark-bg);
  font-style: var(--shiki-dark-font-style);
  font-weight: var(--shiki-dark-font-weight);
}
```

同时把 `.prose pre` 里的 `background: var(--code-bg)` 删掉，否则浅色下它的选择器权重（0-1-1）会压过 `.astro-code`（0-1-0），背景还是深色。

### 2. 未来日期的文章已经上线了

`src/content/posts/focus-and-rest.md` 的 `date: 2026-09-05`，而今天是 **2026-09-03**。构建产物实证：

- `dist/index.html` 列表第一条就是它（`<time datetime="2026-09-05T00:00:00.000Z">9月5日</time>`）
- `dist/rss.xml` 首条 item 是它
- `dist/sitemap-0.xml` 里也有它

所有 `getCollection('posts', ({ data }) => !data.draft)` 只过滤了 `draft`，没过滤未来日期。定时发布只能靠"到那天再 push"，这不可靠。

**修复**：抽一个统一的取文函数（顺便解决 P1-1 的重复代码）：

```ts
// src/utils/posts.ts
import { getCollection, type CollectionEntry } from 'astro:content';

export async function getPublishedPosts(): Promise<CollectionEntry<'posts'>[]> {
  const prod = import.meta.env.PROD;
  const now = new Date();
  const posts = await getCollection('posts', ({ data }) => {
    if (prod && data.draft) return false;
    if (prod && data.date > now) return false;
    return true;
  });
  // 同日文章按 slug 兜底排序，保证构建结果稳定
  return posts.sort(
    (a, b) => b.data.date.valueOf() - a.data.date.valueOf() ||
              a.slug.localeCompare(b.slug),
  );
}
```

### 4. 首页翻页无法用浏览器后退返回

`src/pages/index.astro:164` 用的是 `history.replaceState`：

```js
window.history.replaceState({ ...(history.state ?? {}), scrollX, scrollY }, '', url);
```

翻到第 3 页再点浏览器后退，会直接离开首页（跳到来之前的那个站外/站内页面），而不是回到第 2 页。注释里说这是为了保留 Astro VT 的 `history.state`，方向是对的，但用 replaceState 是拿"保状态"换了"丢历史"。

**两种修法，选一**：

- **小改**：改 `pushState`（同样保留 `history.state`），并监听 `popstate` 把页码重新应用到 DOM：

  ```js
  window.addEventListener('popstate', () => applyPage(currentPage(), true));
  ```

- **大改（推荐）**：用 Astro 的静态分页 `/page/2/`、`/page/3/`，每页一个真实 HTML。好处是首屏 HTML 从 **71 KB 降到 ~15 KB**，`?page=N` 有真实 URL 可被搜索引擎收录，无 JS 也能翻页。代价是首页的"按年份分组"跨页展示要重新设计（或者干脆把年份分组移到新建的 `/archive/` 页）。

### 5. 跨年之后，翻页会留下空的年份标题

分页逻辑只隐藏 `.post-row`，不隐藏 `.year-group`。现在 20 篇文章全在 2026 年所以看不出来；等跨到 2027 年，翻到第 2 页时顶部会留一个孤零零的「2026」标题，下面一篇文章都没有。

**修复**：`applyPage` 里补一步，按组检查是否还有可见行：

```js
for (const group of document.querySelectorAll('.year-group')) {
  group.hidden = !group.querySelector('.post-row:not([hidden])');
}
```

### 7. 搜索索引把代码块全文塞了进去

`src/pages/search.json.ts:6` 的 `stripMarkdown` 只处理了代码围栏的**开始**标记：

```js
.replace(/```[^\n]*\n?/g, ' ')   // 闭合的 ``` 没被清掉
```

结果：20 篇文章的 `search.json` 有 **34.8 KB**，里面混着大量代码和散落的 ``` 符号。用户搜 `function`、`const` 会命中一堆代码块。而且这个文件每次触发搜索都会被全量下载，且**没有任何缓存头**。

**修复**：先剔除围栏内容再压缩，并给正文设上限：

```js
.replace(/```[\s\S]*?```/g, ' ')   // 成对匹配，整块剔除
.replace(/`[^`]*`/g, ' ')          // 行内代码也剔除
```

```js
content: stripMarkdown(post.body).slice(0, 2000),   // 够搜索用了
```

长期方案：文章超过 100 篇后换 [Pagefind](https://pagefind.app/)（Astro 官方推荐，自带中文分词、索引分片、按需加载），比现在的 `includes` 全串匹配强得多。

## P1　工程与内容规范

### 1. `getCollection + sort` 重复了 5 次，其中一次是 O(n²)

同样的四行代码出现在 `index.astro`、`[slug].astro`、`rss.xml.js`、`search.json.ts`、以及 `tags/` 两个页面里。更糟的是 `[slug].astro`：

```js
const posts = (await getCollection('posts', ...)).sort(...);   // 每篇文章都全量拉一次并排序
const index = posts.findIndex((p) => p.id === post.id);        // 再线性查找一次邻位
```

20 篇文章时无所谓，200 篇时就是 200 次全集合排序。Astro 有缓存所以不会真的慢很多，但这个模式不该留着。

**修复**：P0-2 里的 `src/utils/posts.ts`，再补一个邻接查询：

```ts
export function getAdjacent(posts: CollectionEntry<'posts'>[], id: string) {
  const i = posts.findIndex((p) => p.id === id);
  return {
    newer: i > 0 ? posts[i - 1] : null,    // 列表里更靠前 = 更新的
    older: i >= 0 && i < posts.length - 1 ? posts[i + 1] : null,
  };
}
```

### 2. 上一篇/下一篇的语义反了

`[slug].astro:20-21`：`next` 取的是 `posts[index - 1]`，也就是**更新**的那篇；`PostLayout.astro` 把它标成"下一篇"。而列表是倒序的（新的在前），所以"下一篇"指向的是列表里**更靠上**的文章。

中文博客的惯例是「上一篇 = 更新的（列表里前一条）」，这里正好相反。

**修复**：要么交换变量名，要么把 UI 文案改成无歧义的「更新的一篇 / 更早的一篇」——后者更省事，也更清楚。

### 3. 排序不稳定

`sort((a, b) => b.data.date - a.data.date)` 在日期相同时返回 0，此时顺序取决于 `getCollection` 的返回顺序（按文件遍历序）。文件系统顺序在不同机器上可能不同，导致同样的代码构建出不同的页面顺序。加个次级排序键（见 P0-2 代码）即可。

### 4. 日期渲染没有指定时区

`date: 2026-09-05` 被 Zod 解析为 **UTC 午夜**（`2026-09-05T00:00:00.000Z`，构建产物已确认）。`formatDate` 用 `Intl.DateTimeFormat('zh-CN')` 但没指定 `timeZone`，于是取**构建机器的时区**。GitHub Actions 的 runner 是 UTC，本地是 UTC+8——同一个日期在不同时区渲染可能差一天。

**修复**：`timeZone: 'Asia/Shanghai'`。

### 5. 标签系统有两处隐患

- **URL 用中文原文**：生成了 `/tags/性能优化/`、`/tags/流程规范/` 这样的目录。中文路径在部分 CDN、代理、和 Windows CI 上会有编码问题。建议加一层 slug 映射（`src/data/tags.ts` 里加 `slug` 字段，或直接用 pinyin 生成），`getStaticPaths` 输出 slug，`[tag].astro` 反查显示名。
- **描述写死在代码里**：`TAG_DESCRIPTIONS` 现在漏了 `终端`、`SEO`、`流程规范` 三个标签，它们全落到了兜底的"关于该主题的文章"。新增标签必须改代码，这个成本不该由写文章的人承担。建议把描述挪进 content collection（`src/data/tags.json` 或一个新的 `tags` collection），Zod 校验时对未知标签报警。

### 6. `search.astro` 的 `replaceState(null, ...)` 抹掉了 View Transitions 的状态

`search.astro:120`：

```js
window.history.replaceState(null, '', url);
```

而 `index.astro` 小心翼翼地保留了 `history.state`（"含 index，让 Astro 的滚动恢复正常工作"）。搜索页传 `null` 会把这个状态清掉，之后从搜索页做客户端导航时，Astro 的滚动位置恢复会失效。

**修复**：跟首页保持一致，展开旧 state 而不是传 null。

### 7. 四个客户端脚本各自为政

`reveal.ts`、`backButton.ts`、`index.astro` 的内联脚本、`Header.astro` 的内联脚本，四个都在监听 `astro:page-load`，各自 `querySelector`、各自用 `dataset.inited` 去重。逻辑上没错，但：

- `backButton.ts` 的 `theme-toggle` 绑定挂在 `#header-search` 的 `inited` 守卫里（Header.astro:92），两个不相干的关注点耦合在一起
- `Header.astro:223` 的 `pointerdown` 监听挂在模块顶层，依赖"模块只执行一次"这个隐含前提

**修复**：抽一个 `src/scripts/lifecycle.ts`，统一注册一次 `astro:page-load`，其他脚本导出 `init()` 由它调度。

### 8. 硬编码的绝对路径，让 `base` 配置随时会崩

`README.md` 第 68 行提醒用户"GitHub Pages 项目站点需要加 `base: '/仓库名/'`"，但一旦加了，下面这些会全部失效：

- `BaseLayout.astro:51,53` — `/favicon.svg`、`/rss.xml`
- `BaseLayout.astro:40` — `new URL('/og.svg', Astro.site)`
- `scripts/search.ts:84` — `fetch('/search.json')`
- `backButton.ts:40` — `window.location.pathname === '/'` 判断首页
- `Header.astro` — `links` 数组里的 `/`、`/tags/`、`/about/`

**修复**：统一用 `import.meta.env.BASE_URL` 拼前缀，`fetch(`${BASE_URL}search.json`)`；首页判断改成 `path === BASE_URL || path === BASE_URL + '/'`。

## P2　性能与体验打磨

### 1. 首页 HTML 有 71 KB

构建实测：`dist/index.html` **71,362 字节**，而其他页面都是 20 KB 左右。原因是客户端分页把 20 篇文章的完整 DOM 全部内联了。改成静态分页（P0-4）可以直接降到 15 KB 上下。

### 2. 字体占 80 KB，且每页都 preload 两个

`geist-latin-wght-normal.woff2` 29 KB + `source-serif-4-latin-wght-normal.woff2` 51 KB。衬线字体只用在标题上却全量 preload。可以考虑：

- 衬线字体只 preload 首页和文章页（有 h1 的地方）
- 用 `size-adjust` + 系统字体做 fallback 减少 CLS

另外 `<style is:inline set:html={fontFaces}>` 放在 `</body>` 之前（`BaseLayout.astro:115`）——浏览器仍会应用，但字体声明出现在文档末尾，`@font-face` 的解析时机晚于 head 里的 preload，FOIT/FOUT 行为不可控。**移到 `<head>` 里**。

### 3. `prefetchAll: true` 会预取全站所有链接

文章到 100 篇时，访客在首页停留一会儿就会把 100 个页面全预取一遍。建议改 `defaultStrategy: 'viewport'`（只预取进入视口的链接），收益接近、成本小得多。

### 4. sticky header 会遮住锚点

`html { scroll-behavior: smooth }` + `position: sticky` 的组合下，跳转到 `#xxx` 时标题会被 3.75rem 的 header 盖住。加一行：

```css
html { scroll-padding-top: calc(var(--header-h) + 1rem); }
```

### 5. 搜索框的 ARIA 不完整

- `role="listbox"` 的容器里，`<li>` 没有 `role="option"`
- input 缺 `role="combobox"` / `aria-expanded` / `aria-activedescendant`
- 键盘高亮用的是 `.active` class，没有同步到 `aria-activedescendant`，屏幕阅读器用户不知道选中了哪条

这是全站交互最复杂的组件，值得补完。

### 6. 缺 robots.txt

有 `sitemap-index.xml`，但没有 `robots.txt` 指向它。加一个 `public/robots.txt`：

```
User-agent: *
Allow: /

Sitemap: https://azainl.github.io/sitemap-index.xml
```

### 7. OG 图全站共用一张静态图

`public/og.svg` 是所有页面唯一的分享预览图。分享单篇文章到微信/推特时，看到的是站点通用图。可以用 `satori` + `sharp` 在构建时为每篇文章生成带标题的 OG PNG（Astro 有 `astro-og-canvas` 这类现成方案）。

### 8. CSS 单文件 1240 行，有重复定义

- `.archive` 定义了两次（485 行、577 行）
- `.site-nav a` 定义了两次（182 行、200 行）
- 分类注释已有，但混在一起后"翻页"相关的规则散落在首页区块里

建议按 `@layer base, components, pages` 拆成 3~4 个文件，Astro 会自动合并成一个 bundle，不影响产物。
