### 4.3 客户端脚本生命周期

这是本项目最容易被改坏的地方。

**问题**：Astro 的 View Transitions 会让页面「不刷新地」切换，普通 `DOMContentLoaded` 只在首次触发，切页后新 DOM 上的事件监听全部失效。

**解法**：`src/scripts/lifecycle.ts` 统一用 `astro:page-load` 调度，所有交互模块都注册到这里：

```
lifecycle.ts  →  reveal.ts      滚动渐显
              →  search.ts      搜索（Header 内）
              →  backButton.ts  返回按钮语义
              →  vtAxis.ts      视图过渡坐标轴
              →  randomPost.ts  页脚「随便看看」升级为随机打开一篇
```

（`randomPost` 从 T-39 起也走 `onPageLoad`，见 `src/scripts/randomPost.ts:14,95`。）

**新增交互模块时**：不要自己写 `addEventListener('DOMContentLoaded')`，要挂进 lifecycle。否则首次访问能用、切一次页面就失效。

**另一个坑（已修）**：`BaseLayout.astro` 原有个 `<script is:inline>` 同步加 `.js` 类，配合 `effects.css` 的 `.js .reveal { opacity: 0 }` 实现「先隐藏、JS 接管后再渐显」。**当年这是个渐进增强反模式**——模块脚本加载失败时正文永久空白（兜底只在 CSS 也丢时才生效）。现在 `BaseLayout` 的内联脚本会在 `DOMContentLoaded` 检查 `root.dataset.revealReady`，未接管就 `remove('js')`。详见 §7-A1。**改这块之前务必读 A1**。

### 4.5 搜索

**数据流**：构建期生成 `/search.json`（49 KB，含标题/描述/日期/标签/**正文前 500 字**）→ 运行时首次聚焦搜索框时按需 fetch → 客户端过滤 + 高亮。

**已做的优化**：
- 索引**按需加载**（`Header.astro`），不在每页顶层拉取。T-13 之前是每页无条件拉索引，连 404 页都拉。
- 高亮用 `createTextNode + replaceChildren`，**不用 innerHTML** → 无 XSS。
- ARIA 完整：`combobox` / `listbox` / `option` / `aria-activedescendant` 全套，关闭时统一复位 `aria-expanded`。

**注意**：`search.json` 现在是 **49905 B raw / 22629 B gzip**，32 条，其中 20 条正文达到 500 字截断上限（T-21 把正文从全文改成 `slice(0, 500)` 后的体积；改前是 59049 B）。截断阈值与「100 篇 < 100 KB」这条验收口径写在 `docs/后续功能开发计划.md` §3.1。到 `PAGEFIND_THRESHOLD = 80` 篇时会 `console.warn` 提示换 Pagefind（见 §7-C2）。

### 4.6 OG 图与结构化数据

#### A2. JSON-LD 注入漏洞（S-1）—— ✅ 已解决

> 修复：`src/utils/jsonld.ts` 新增 `safeJsonLd()`（`<` `>` `&` `U+2028` `U+2029` → JSON 转义），**当时**四处调用点全部替换。已固化为回归断言（源码契约 + 产物逐块可解析）。下文为问题原貌。
> （「四处」是修复时的数量；现在产出 JSON-LD 的页面已增至 9 处，见 §4.6 与 `check.mjs` 的 `>= 9` 下限。）

**证据**：四处裸 `JSON.stringify` 直接 `set:html`：

| 文件 | 行 |
|---|---|
| `src/layouts/PostLayout.astro` | 84 |
| `src/pages/index.astro` | 69 |
| `src/pages/page/[page].astro` | 54 |
| `src/pages/tags/[tag].astro` | 59 |

写法（示例，实际就是这一行）：

```astro
<script type="application/ld+json" is:inline set:html={JSON.stringify(jsonLd)} slot="ld" />
```

`JSON.stringify` **不转义 `<` 和 `>`**。文章标题或摘要里只要出现 `</script>`，后面的内容就会被浏览器当 HTML 解析。

**本次交接实测复现**：探针文章的 title/description 各塞了一个 `</script><script>...</script>` 片段，构建产物里：

```
JSONLD_HEAD = {"@context":"https://schema.org","@graph":[{"@type":"BlogPosting",
              "headline":"探针：关于 </script> 标签的一个坑",
              "description":"PROBE</script><script>window.__hit=...</script>",...
STRAY_SCRIPT_COUNT = 14
BODY_LEAKED = True          ← 片段泄漏进可见正文
```

**这不是理论漏洞**：写一篇**讲 HTML 转义的文章**就会自然触发。

**修复方案**（报告 §2.4 已给，直接照做）：

在 `src/utils/jsonld.ts` 新增 `safeJsonLd(data)`，把 `<` `>` `&` `U+2028` `U+2029` 转成 JSON 转义序列（`\u003c` 等）。**不能用 HTML 实体**——`<script>` 是原始文本元素，不解码实体。

```typescript
const ESCAPE = { '<': '\\u003c', '>': '\\u003e', '&': '\\u0026',
                 '\u2028': '\\u2028', '\u2029': '\\u2029' };
export function safeJsonLd(data: unknown): string {
  return JSON.stringify(data).replace(/[<>&\u2028\u2029]/g, (c) => ESCAPE[c]);
}
```

然后**四个调用点全部换成 `safeJsonLd`**。

**验收**：`grep safeJsonLd src/` 必须命中 5 处（1 定义 + 4 调用）；用含 `</script>` 的探针文章构建，`STRAY_SCRIPT_COUNT` 必须为 0。

> 现状：`grep safeJsonLd src/` 命中 **5 处**（1 定义 + 4 调用），已落地。
