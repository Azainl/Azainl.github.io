## 0. 这份文档解决什么问题

项目有四份历史文档（`操作文档.md`、`安全审查报告.md`、`代码审查与优化建议.md`、`技能驱动的开发计划与任务书.md`），质量都不错，但**它们写于不同时间点，数字和状态已经漂移**。另有 `任务三处理记录.md`（P0 阶段遗留清单处置）、`任务四处理记录.md`（P1 三项新功能落地）与 `任务五处理记录.md`（P1-4 内容侧工程化）三份**逐条处置记录**，文末均标注未提交状态。

### 4.3 客户端脚本生命周期

这是本项目最容易被改坏的地方。

**问题**：Astro 的 View Transitions 会让页面「不刷新地」切换，普通 `DOMContentLoaded` 只在首次触发，切页后新 DOM 上的事件监听全部失效。

**解法**：`src/scripts/lifecycle.ts` 统一用 `astro:page-load` 调度，所有交互模块都注册到这里：

```
lifecycle.ts  →  reveal.ts      滚动渐显
              →  search.ts      搜索（Header 内）
              →  backButton.ts  返回按钮语义
              →  vtAxis.ts      视图过渡坐标轴
```

**新增交互模块时**：不要自己写 `addEventListener('DOMContentLoaded')`，要挂进 lifecycle。否则首次访问能用、切一次页面就失效。

**另一个坑（已修）**：`BaseLayout.astro` 原有个 `<script is:inline>` 同步加 `.js` 类，配合 `effects.css` 的 `.js .reveal { opacity: 0 }` 实现「先隐藏、JS 接管后再渐显」。**当年这是个渐进增强反模式**——模块脚本加载失败时正文永久空白（兜底只在 CSS 也丢时才生效）。现在 `BaseLayout` 的内联脚本会在 `DOMContentLoaded` 检查 `root.dataset.revealReady`，未接管就 `remove('js')`。详见 §7-A1。**改这块之前务必读 A1**。

### 4.5 搜索

**数据流**：构建期生成 `/search.json`（59 KB，含标题/描述/日期/标签/**正文全文**）→ 运行时首次聚焦搜索框时按需 fetch → 客户端过滤 + 高亮。

**已做的优化**：
- 索引**按需加载**（`Header.astro`），不在每页顶层拉取。T-13 之前是每页无条件拉索引，连 404 页都拉。
- 高亮用 `createTextNode + replaceChildren`，**不用 innerHTML** → 无 XSS。
- ARIA 完整：`combobox` / `listbox` / `option` / `aria-activedescendant` 全套，关闭时统一复位 `aria-expanded`。

**注意**：`search.json` 现在是 **59049 B raw / 26546 B gzip**，而文档里记的是 29.5 KB。正文全文索引随文章数增长——32 篇时 59 KB，100 篇时会到 ~180 KB。**已决策维持现状，到 `PAGEFIND_THRESHOLD = 80` 篇时换 Pagefind**（见 §7-C2）。

### 4.6 OG 图与结构化数据

- **OG 图**：`public/og/<slug>.png` 32 张 + 兜底 `og.png`。生成脚本 `scripts/generate-og.mjs`，清单在 `src/data/og-manifest.ts`。**加新文章后要跑 `npm.cmd run og` 并提交新图**。漏跑不会让页面报错（`ogImagePath` 会回退到兜底图），但 `npm run check` 里的「OG 清单与文章集合一致」断言会 FAIL —— 这就是它存在的意义。
- **JSON-LD**：`src/utils/jsonld.ts` 提供 `breadcrumbList` / `webSiteRef` / `collectionPage`；文章页的 `BlogPosting` 在 `PostLayout.astro` 内联构造。
- ✅ **JSON-LD 注入漏洞（S-1）已修**：所有输出点走 `safeJsonLd()`（转义 `<` `>` `&` `U+2028` `U+2029`），见 §7-A2。当前源码中 `safeJsonLd(` 共 **7 处**（1 处定义 + 6 处调用：文章页/首页/标签页/分页页/归档页/系列页），`check.mjs` 的下限断言已同步上调为 7——**每新增一个产出 JSON-LD 的页面，这个下限必须同步上调**，否则新页面可以用裸 `JSON.stringify` 绕开闸门。

## 5. 约定与规矩

### 5.1 写文章

1. 在 `src/content/posts/` 新建 `.md`，**文件名即 slug，必须 kebab-case**；
2. frontmatter 按 §4.1 的表填；
3. 图片放 `src/assets/images/`，用相对路径引用（走 Astro 优化管线，自动 webp）；
4. 草稿加 `draft: true`——**注意 dev 模式反而只显示草稿**（§4.1）；
5. 跑 `npm.cmd run og` 生成 OG 图。
6. **可选**：要让文章进入某个系列，加 `series: '<系列名>'` + `seriesOrder: <正整数>`；系列名要先在 `src/data/series.ts` 的 `SERIES` 里登记，否则走「小写 + 空格转连字符」兜底、系列页描述会缺。**没有这两个字段的文章行为完全不变**（P1 验收项，已有断言守护）。

### 5.2 重命名文章 = 必须配重定向

改 slug 或改标签 slug 后，**必须在 `astro.config.mjs` 的 `redirects` 表里加一条**。当前有 5 条文章重定向 + 11 条标签重定向。

> ⚠️ **Windows/macOS 大小写陷阱**：`astro.config.mjs` 里有明确注释——**不要**给仅大小写不同的 ASCII 标签（如 `Astro` → `astro`、`SEO` → `seo`）加重定向。在大小写不敏感的文件系统上会造成自我重定向死循环。这是个已经踩过并记录的坑。

### 5.3 标签

标签定义集中在 `src/data/tags.ts`（12 个标签 + 4 个分组）。新增标签要在这里登记 `name / slug / description`，否则会走「小写 + 空格转连字符」的兜底逻辑。

### 5.4 提交与发布

```powershell
git add -A
git commit -m "docs(posts): 新增文章 xxx"
git push
```

推送后 GitHub Actions 自动构建部署，约 1 分钟。提交信息风格参考 `git log`：`类型(范围): 说明`，类型有 `feat` / `fix` / `docs` / `perf` / `chore`。

### 5.5 脚本路径

`scripts/*.mjs` 一律用 `import.meta.url` 推导路径，**不要硬编码绝对路径**（历史问题 P0-9，已修）。

### 5.6 改 `astro.config.mjs` 前先看这一段

这个文件在**配置加载期**直接读文件系统（`readPosts()` 读 frontmatter、`readTagSlugs()` 正则解析 `tags.ts`）。改它的时候：

- 解析逻辑一坏，**构建直接失败**（不是运行时问题）；
- `sitemap` 的 `lastmod` 语义是：文章用 `updated || date`，列表类用最新文章日期，关于页/搜索页不给；
- `image.layout: 'constrained'` + `responsiveStyles: true` 决定了图片只输出 webp。

#### A1. JS 加载失败时正文永久空白 —— ✅ 已解决（提交 `d5794a6`）

> 下文记录的是**问题原貌**。实际修复：`BaseLayout.astro` 的内联脚本在 `DOMContentLoaded` 检查 `root.dataset.revealReady`，模块脚本若未接管就 `remove('js')`；`reveal.ts:9` 在模块求值处写 `revealReady`。实测阻断 `*/_astro/*.js` 时 `.prose` computed opacity = 1。已固化为回归断言。

```
src/styles/effects.css:5      .js .reveal { opacity: 0 }

src/scripts/reveal.ts                 加 .is-visible                 ← 模块脚本，可能丢
```

| 场景 | `.prose` computed opacity |
|---|---|

#### A2. JSON-LD 注入漏洞（S-1）—— ✅ 已解决

> 修复：`src/utils/jsonld.ts` 新增 `safeJsonLd()`（`<` `>` `&` `U+2028` `U+2029` → JSON 转义），四处调用点全部替换。已固化为回归断言（源码契约 + 产物逐块可解析）。下文为问题原貌。

**证据**：四处裸 `JSON.stringify` 直接 `set:html`：

| 文件 | 行 |
|---|---|
| `src/layouts/PostLayout.astro` | 84 |
| `src/pages/index.astro` | 69 |
| `src/pages/page/[page].astro` | 54 |
| `src/pages/tags/[tag].astro` | 59 |

写法（示例，实际就是这一行）：

```astro
<script type="application/ld+json" is:inline set:html={JSON.stringify(jsonLd)} slot="ld" />
```

`JSON.stringify` **不转义 `<` 和 `>`**。文章标题或摘要里只要出现 `</script>`，后面的内容就会被浏览器当 HTML 解析。

**本次交接实测复现**：探针文章的 title/description 各塞了一个 `</script><script>...</script>` 片段，构建产物里：

```
JSONLD_HEAD = {"@context":"https://schema.org","@graph":[{"@type":"BlogPosting",
              "headline":"探针：关于 </script> 标签的一个坑",
              "description":"PROBE</script><script>window.__hit=...</script>",...
STRAY_SCRIPT_COUNT = 14
BODY_LEAKED = True          ← 片段泄漏进可见正文
```

**这不是理论漏洞**：写一篇**讲 HTML 转义的文章**就会自然触发。

**修复方案**（报告 §2.4 已给，直接照做）：

在 `src/utils/jsonld.ts` 新增 `safeJsonLd(data)`，把 `<` `>` `&` `U+2028` `U+2029` 转成 JSON 转义序列（`\u003c` 等）。**不能用 HTML 实体**——`<script>` 是原始文本元素，不解码实体。

```typescript
const ESCAPE = { '<': '\\u003c', '>': '\\u003e', '&': '\\u0026',
                 '\u2028': '\\u2028', '\u2029': '\\u2029' };
export function safeJsonLd(data: unknown): string {
  return JSON.stringify(data).replace(/[<>&\u2028\u2029]/g, (c) => ESCAPE[c]);
}
```

然后**四个调用点全部换成 `safeJsonLd`**。

**验收**：`grep safeJsonLd src/` 必须命中 5 处（1 定义 + 4 调用）；用含 `</script>` 的探针文章构建，`STRAY_SCRIPT_COUNT` 必须为 0。

> 现状：`grep safeJsonLd src/` 命中 **5 处**（1 定义 + 4 调用），已落地。

### 🟡 C. 体验与可扩展性

#### C1. S-2：Markdown 正文允许原始 HTML（含 `<script>`）—— ✅ 已决策：接受并文档化

**决策**：维持现状（接受原始 HTML）。理由——本站是「作者写、作者发」的单作者个人博客，无评论、无投稿、无外部 CMS、无用户输入，原始 HTML 在本语境下是**特性而非漏洞**（如手写 `<details>`、内联 SVG 等）。

#### C2. `search.json` 体积线性增长 —— ✅ 已决策：维持现状，到阈值换 Pagefind
