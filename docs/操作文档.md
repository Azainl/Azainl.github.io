## 1. 快速开始

```powershell
# 进入项目目录
cd D:\Code\Deepseek\blog

# 安装依赖（只需一次；如果之前装过可跳过）
npm.cmd install

# 本地开发：启动后浏览器打开 http://localhost:4321
npm.cmd run dev

# 构建线上版本（输出到 dist/）
npm.cmd run build

# 预览构建结果
npm.cmd run preview
```

> **本机注意**：PowerShell 默认禁止运行 `npm.ps1` 脚本，所以本机统一用
> `npm.cmd` 而不是 `npm`。如果执行 `npm` 报"禁止运行脚本"，换 `npm.cmd` 即可。

发布到线上只需一条命令组合：

```powershell
git add -A
git commit -m "更新内容"
git push
```

推送后 GitHub Actions 会自动构建并部署，约 1 分钟后线上更新。

## 3. 写文章（最常用）

### 3.1 新建一篇文章

在 `src/content/posts/` 下新建一个 Markdown 文件即可。文件名就是文章的网址
（slug），**只能用英文小写 + 连字符（kebab-case）**，例如 `my-first-post.md`
对应网址 `https://azainl.github.io/posts/my-first-post/`。

文件头部必须写 frontmatter（两行 `---` 之间的内容）：

```md
---
title: "文章标题"
description: "文章摘要，显示在首页列表、搜索引擎和分享卡片里"
date: 2026-08-03
tags: ["随笔", "思考"]
draft: false
---

正文从这里开始，支持标准的 Markdown 语法。
```

### 3.2 frontmatter 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `description` | 是 | 摘要，建议一句话说清文章内容 |
| `date` | 是 | 发布日期，格式 `YYYY-MM-DD` |
| `tags` | 否 | 标签数组；每个标签生成 `/tags/<slug>/` 页面（URL 用英文 slug，映射见 `src/data/tags.ts`） |
| `draft` | 否 | `true` 时文章只在本地可见，不会发布 |
| `updated` | 否 | 修改日期，格式同 `date`，**不能早于 `date`**；填了之后文章页显示「更新于」，并同步到 JSON-LD 的 `dateModified` 与 RSS 的 `lastBuildDate` |
| `featured` | 否 | `true` 时进首页「精选文章」区块（建议最多 3 篇） |

字段缺失或日期格式错误时，构建会直接报错（这是保护机制，防止坏数据上线）。
`draft: true` 与**未来日期**的文章都不会进入线上产物，但本地 `npm run dev`
下仍可见，方便预览定时发布。
标签页会显示每个标签的一句话描述，定义在 `src/data/tags.ts` 里，可自由增改。
新增标签时建议在该文件里补一行 slug，否则 URL 会退化成百分号编码。

> **改了文章标题后记得跑一次 `npm.cmd run og`**，重新生成社交分享卡片图。
> 分享图是预生成并提交进仓库的（构建时不生成，CI 因此不需要 sharp 和中文字体）；
> 漏跑不会报错，只会让这篇文章回退成全站默认图。新增/删除文章同理。

### 3.3 支持的 Markdown 语法

标题、段落、**加粗**、*斜体*、[链接](https://example.com)、
`行内代码`、列表、引用、表格、代码块（带语法高亮）都支持。

```md
## 二级标题

### 三级标题

> 这是引用，会显示成带左边线的样式

- 列表项一
- 列表项二

1. 有序列表一
2. 有序列表二

| 表头一 | 表头二 |
| --- | --- |
| 内容 | 内容 |

    ```js
    console.log('代码块自动高亮');
    ```
```

### 3.4 插入图片

把图片文件放进 `src/assets/images/`，然后在文章里用**相对路径**引用：

```md
![图片说明](../../assets/images/文件名.jpg)
```

图片会**自动经过 Astro 的图片管道**（astro:assets），每次构建产出：

| 自动获得 | 说明 |
| --- | --- |
| WebP | 实测比等效 JPEG 小约 30% |
| `srcset` 多档 | 640 / 750 / 828 / 1080 / 1152w，浏览器按视口与 DPR 自取 |
| `width` / `height` | 浏览器可提前预留空间，**避免图片加载时的布局抖动** |
| `loading="lazy"` | 首屏外不加载 |
| 内容哈希文件名 | `/_astro/名字.<hash>.webp`，可长期强缓存 |

**不需要预先压图**：源图给大一点没关系（推荐宽 **1152px** 即可覆盖 2x 屏），
输出档位由构建时自动生成，访客只会下到需要的那一档。

> 实测收益（`checks-1.jpg`，源 1152×648 / 46 KB）：
> 桌面 DPR1 原要下 1152w 的 31.1 KB，修复后只下 640w 的 **15.4 KB（省 50%）**；
> 手机 DPR2 下 828w 的 21.1 KB。

> ⚠️ **两个容易踩的点**
> 1. 相对路径的层级是相对**文章文件**算的：文章在 `src/content/posts/`，
>    图片在 `src/assets/images/`，所以要写 `../../`，写成 `../` 会报
>    `ImageNotFound` 构建失败。
> 2. 文字说明里的 `sizes` 由 `plugins/markdown-image-sizes.mjs` 统一注入。
>    它写死了 36rem（=576px），这个值来自 `src/styles/pages.css` 的 `.prose img`，
>    **改 CSS 上限时务必同步改那个插件**，否则浏览器会挑错档位、白下流量。

**署名要跟图源对上**。题图下面那行斜体是版权行，格式由
`.prose p:has(img) + p:has(em)` 自动套用，但**内容得你自己写准**：

| 图源 | 署名写法 |
| --- | --- |
| 早期几张，来自 Flickr | `*题图来自 Flickr，CC 授权*` |
| 新的图，来自 Unsplash | `*题图来自 Unsplash，摄影 <作者>*` |

> 找图：`loremflickr` 目前返回 401 已不可用，可改用
> `https://picsum.photos/id/<id>/1200/675`（固定 `id` 保证每次同一张）；
> 作者名从 `https://picsum.photos/id/<id>/info` 取。
> **下载后务必打开看一眼**——占位图服务偶尔会返回内容完全不搭的图。

### 3.5 阅读时长

阅读时长是自动计算的（中文按 400 字/分钟估算），无需手动填写。

### 3.6 草稿与预览

把 `draft: true` 的文章推送到 GitHub 不会出现在线上；在本地 `npm.cmd run dev`
时仍然可以看到，方便先写后发。

> **补充：未来日期也是同理。** 如果 `date` 写的是未来的某天（用于定时发布），
> 线上会等到那天才出现这篇文章；但在本地 `npm.cmd run dev` 下能直接预览效果。
> 这套"生产过滤 / 开发可见"的逻辑统一在 `src/utils/posts.ts` 的
> `getPublishedPosts()` 里。

### 3.7 重命名或删除文章（要配重定向）

文章一旦发布，URL 就会出现在 RSS、外链、搜索引擎里。**直接改文件名或删文件会让
这些旧链接 404**。正确做法：

1. 改文件名后，在 `astro.config.mjs` 的 `redirects` 里加一条旧路径 → 新路径的映射，
   例如：
   ```js
   redirects: {
     '/posts/旧文件名/': '/posts/新文件名/',
   }
   ```
2. 静态构建会为每个旧路径生成带 `meta refresh` 的重定向页，GitHub Pages /
   Netlify / Vercel 都能用，无需平台额外配置。
3. 删除文章同理——如果这篇文章曾被外链引用，也加一条重定向到首页或同类文章。

> 走 `src/utils/posts.ts` 统一取数的页面（首页、文章页、RSS、搜索、标签页）都会
> 自动跟随文件变化，无需逐个改引用。

## 4. 修改站点信息

所有站点配置集中在 `src/consts.ts`，只改这一个文件即可：

```ts
export const SITE = {
  name: 'Azain',                    // 站点名（页脚等位置显示）
  title: '山月 · 个人博客',          // 浏览器标签页标题
  description: '一个关于代码、阅读与生活的个人博客。', // 站点简介
  author: 'Azain',                  // 作者名（关于页使用）
  email: '2013386765@qq.com',       // 联系邮箱（关于页显示）
  locale: 'zh-CN',
};
```

> **域名只在 `astro.config.mjs` 的 `site` 里配置**：RSS、sitemap、canonical、
> `og:url` 全部由它派生。`consts.ts` 里曾经有一个从不被任何代码引用的 `url`
> 字段，两处配置容易只改一处，已删除。

修改后执行 `npm.cmd run build` 确认没有报错，再 `git push` 发布。

另外两处可选的独立修改：

- 页头左上角的文字（站点标识）：`src/components/Header.astro` 里的
  `Az<span>ain</span>`（**硬编码**，不会随 `consts.ts` 的 `name` 自动变化）。
  如果换了站点名，这里和 `SITE.name`（用于 `aria-label`、页脚、各页 `<title>`）
  要一起改，否则标识和朗读/标题会对不上。
- 站点图标：替换 `public/favicon.svg`。
- 分享预览图：**不是**换个文件那么简单。全站默认图是 `public/og.png`，
  每篇文章的专属图由 `npm run og` 从文章标题生成（见第 3 节）。
  要改样式就改 `scripts/generate-og.mjs` 里的卡片模板，然后重跑一次。
  > 曾经这里写的是「替换 `public/og.svg`」—— 但 SVG **不能**作为 `og:image`
  > （Facebook / Twitter / LinkedIn 都不解析），照做等于分享出去没有预览图。

## 5. 修改设计（外观）

全站样式在 `src/styles/` 下，由 `global.css` 作为入口 `@import` 六个分片
（`base` / `header` / `home` / `pages` / `effects` / `post-extras`）。
**@import 的顺序就是层叠顺序，不要调换**。设计令牌在 `base.css` 顶部。
改配色/字体改 `base.css`，改首页排版改 `home.css`，以此类推。

### 5.0 设计系统（改之前先读这一节）

本站在 2026-10 明确锚定了一套设计语言，**以 Stripe Press 的暖纸材质为基准，
Monocle 的「刊头 → 标题 → 导语」三级层级为版式基准，Tufte 的"细线即全部装饰"
为克制基准**。改动时请遵守三条判据，否则很容易退回"通用 AI 页面"的观感：

| 判据 | 具体约束 | 实测值 |
| --- | --- | --- |
| **材质是暖纸，不是白** | 底色必须带暖调，灰也必须有暖调；浮层靠明度差区分而非阴影 | `--bg #f2ede1`，与 `--surface` 差 1.10:1 |
| **正文用衬线** | 正文、标题、摘要、导语全部衬线；无衬线只服务界面（导航、元信息、按钮） | `.prose` = Source Serif 4 |
| **行宽按字数控** | `.prose` 必须受 `--measure` 约束，目标 30 个中文字/行 | 实测 30.2 字/行 |

**层级靠"字号 + 字重 + 细线"，不靠换字体或加色块**：

| 层级 | 字体 | 字号 |
| --- | --- | --- |
| 报头 | 衬线 600 | 32→46px（clamp） |
| 页面/文章标题 | 衬线 600 | 44px |
| 区块标题 | 衬线 600 | 28px |
| 条目标题 | 衬线 600 | 20px |
| 阅读正文 | 衬线 400 | 18px |
| 界面文字 | 无衬线 | 15px |
| 元信息 | 等宽 13px，`tabular-nums` | 13px |
| 标签 | 等宽 | 13px |

> ⚠️ **改底色必须重算强调色对比度**。朱砂红 `#b44126` 是在暖纸 `#f2ede1`
> 上算出来的（5.03:1，达 WCAG AA）；旧值 `#c5321a` 在新底上只有 4.67:1。
> 换底色后请用同样的方法复算，别直接沿用十六进制。

#### 页头必须不透明（别再用毛玻璃）

页头**不能**写成半透明 + `backdrop-filter`。这处踩过一个很隐蔽的坑：

源文件里若同时写 `backdrop-filter` 和 `-webkit-backdrop-filter`，构建器会按
「同一属性的重复声明」**只保留最后一条**，产物里只剩下 `-webkit-` 前缀版本；
而 Chrome 并不认这个前缀别名（`CSS.supports('-webkit-backdrop-filter', …)` 为
`false`）。结果是页头既半透明、又没有任何模糊兜底 —— 滚动时正文直接透上来，
压在搜索框上，看起来就是"搜索框颜色被盖住了"。

现在 `.site-header` 用不透明 `var(--bg)`。**改这一处前先读 header.css 顶部注释。**
`npm run check` 里有两条断言守着（底色 alpha 必须 = 1；不依赖 backdrop-filter）。

#### 单页阅读版式：题头与正文必须同一条左边缘

「关于」这类"题头 + 正文"的独立页面，**不能**把两个各自居中的盒子上下叠放：

```html
<!-- ❌ 错位写法 -->
<div class="page-head">…</div>            <!-- max-width: 58rem, margin: 0 auto -->
<div class="container prose">…</div>      <!-- max-width: 34rem, margin: 0 auto -->
```

两个盒子都 `margin: 0 auto`，于是**各自**在视口里居中 —— 实测 1440px 下
标题左边缘 271px、正文左边缘 463px，**错位 192px**。标题宽得像版面横幅，
正文却缩在中间一条窄柱里，看着像两段互不相干的内容。

正确写法是用 `.reading` 把它们包进**同一条阅读列**（宽 `--measure + 2.5rem`）：

```html
<div class="reading">
  <div class="page-head">…</div>
  <div class="prose">…</div>
</div>
```

这与文章页（`.post`）是同一套结构 —— 标题、正文、导语共用左右边缘。
`.reading .page-head` 会把自己的宽度与居中一并撤掉，否则它会把标题重新推出去。

> 为什么是收窄题头、而不是把正文加宽到 58rem？因为 58rem 下正文约 46 字/行，
> 远超 30 字的可读上限（见 5.0 判据三）。宁可让标题离开全站脊柱，
> 也不能牺牲行宽。

`npm run check` 的「关于页版式」用例逐边比对标题与正文的 left / right（容差 2px），
并检查无横向溢出。

#### 页头搜索框：保留打开动画，只把"未打开时的底色"钉住

这个控件的**动画**与**底色**是两件事，要分开处理：

**动画（保持原样，不要动）：**

```css
.header-search-input {
  width: 180px;                        /* 未打开 */
  border: 1px solid transparent;       /* 四边都占 1px，但不产生布局位移 */
  border-bottom: 1px solid var(--line);
  transition: border-color 0.15s ease, box-shadow 0.15s ease,
              background-color 0.15s ease, width 0.2s ease;
}
.header-search-input:focus {
  width: 240px;                        /* 聚焦时向左延展 */
  border-color: var(--accent);         /* 一条线 → 四边长成盒子 */
  box-shadow: 0 0 0 3px var(--accent-soft);
}
```

点开时输入框向左延展 60px、下划线长成完整的盒子，这是页头唯一一处"活"的动作。

**底色（唯一需要改的地方）：**

原写法未打开时是 `transparent`，聚焦才变成 `var(--surface)` 纸面。
实测两态 computed 并不一致：

| | background | width | 边框 |
| --- | --- | --- | --- |
| 未打开 | `rgba(0, 0, 0, 0)` | 180px | 仅下边 1px `--line` |
| 聚焦 | `rgb(251, 248, 241)` | 240px | 四边 1px 朱砂 + 光晕 |

于是点开的瞬间底色"刷"地由透变白 —— **颜色先于动画跳了一步**。
现在未打开时就取 `--surface`，底色两态同值、不参与变化。

> **不要把宽度也钉死。** 曾试过固定 `width: 220px`「两态同尺寸」，
> 抽动确实没了，但打开时唯一的动感也一并被抹掉 —— 那是治错了病。
> 「点开不抽动」的正解是让**页头其余部分**不受影响（搜索框右对齐、
> 向**左**延展，所以左邻导航与右邻主题按钮都不会动），而不是取消动画。

`npm run check` 的「搜索框开合一致」用例断言五条：
底色两态同值 · 未打开时底色已是实色（不是 transparent）·
打开时宽度延展 ≥ 40px 且高度不变 · **点开时页头其余部分（刊头/导航/主题按钮）
零位移** · 聚焦四边点亮。前两条守住本次改动，中间两条守住"动画还在"，
最后一条避免奖励一个死掉的焦点态。

#### 首页标签与分割线的间距

标签是 `<a>` 的**兄弟节点**，所以上间距 = `<a>` 的 24px 下内边距 + 标签 8px 外边距
= 32px，而下间距只由标签自己的 `margin-bottom` 决定。原为 0 时，实测标签底
535.4 与分割线 535.4 完全重合，视觉上"坠"在下边。

现在 `.post-row .tag-list` 的 `margin-bottom` 取 `--space-8`(32px)，上下对称。
**不要改用负 margin 去抵消 `<a>` 的内边距** —— 那会让没有标签的行也跟着缩进。
`npm run check` 有断言逐行比对"上方间距 vs 下方间距"，并列出贴线的行数。

### 5.2 字体

字体是**自托管的可变字体**，不依赖外部服务，在 `src/layouts/BaseLayout.astro`
里通过 `@fontsource` 包的 woff2 文件直接引入并内联声明（只取拉丁子集，避免下载
无用字符）：

```ts
// 直接指向具体 woff2 文件，拿到它构建后的 URL
import geistUrl from '@fontsource-variable/geist/files/geist-latin-wght-normal.woff2?url';
import serifUrl from '@fontsource-variable/source-serif-4/files/source-serif-4-latin-wght-normal.woff2?url';
```

然后在同一文件 `<head>` 内：用 `<style is:inline>` 写两段 `@font-face` 声明，并
`<link rel="preload">` 提前加载这两个字体（声明必须和 preload 同处 `<head>`，
否则字体声明晚于预加载，FOIT/FOUT 行为不可控）。

字体栈定义在 `base.css` 的 `--font-sans` / `--font-serif` / `--font-mono`。
中文回退用系统字体（PingFang SC / 微软雅黑 / 思源宋体…），不额外下载中文字体。

> **无衬线只用于界面**。如果把正文改成 `--font-sans`，等于放弃这套配方的
> 识别度来源 —— 那是"又一个 Astro 博客"最常见的观感。

### 5.3 布局与圆角

- **全站只有一条文字脊柱**：`--container-wide`（58rem）。
  页头、报头、列表、区块标题、页脚共用同一条左边缘（实测均为 256px）。
  新增页面请沿用，不要另立宽度 —— 宽度分歧会让页面看起来像几块拼起来的。
- **两类页面例外，走"阅读列"** `calc(--measure + 2.5rem)`：
  - `.post`（文章页）——好让标题与正文共用左右边缘，右侧紧邻目录浮层。
    **改这个宽度要同步核对目录的 `right` 公式**。
  - `.reading`（关于页这类"题头 + 正文"的独立页）——见 5.0「单页阅读版式」。
  这两者是有意离开全站脊柱的：58rem 下正文约 46 字/行，会破坏行宽判据。
- **正文列**由 `.prose` 的 `--measure`（34rem）约束，不要再给 `.post` 加窄限。
- 圆角收敛为 4 档：`--radius-none`(0) / `--radius`(4px) / `--radius-inline`(3px) /
  `--radius-pill`(全圆)。**纸面元素（图片、代码块外框）保持 0~4px 的硬边**，
  全圆只留给"标记"类元素（如「推荐」徽章）。
- 间距用 8pt 体系：`--space-1`(4) 到 `--space-24`(96px) 共 9 档。
  新增样式请从这里取值，不要发明 `2.85rem` 这类一次性数值。
- 首页文章列表、文章页排版分别在 `src/pages/index.astro` 和
  `src/layouts/PostLayout.astro`。

### 6.3 修改导航和页脚

- 导航链接：`src/components/Header.astro` 里的 `links` 数组
- 页脚内容：`src/components/Footer.astro`
- **文章标题上方的返回按钮**：在文章页标题（`post-header`）上方显示，不占用顶部栏。
  点击回到**来源页面**（进入本页时所在的那个历史条目），而不是浏览器历史的上一条。
  返回走浏览器历史 + View Transitions（带动画、不整页刷新），并恢复来源页的滚动位置。
  实现见 `src/scripts/backButton.ts`。

  **为什么不能直接用 `history.back()`**：正文目录（TOC）的锚点链接会让浏览器
  **压入同页的新历史条目**（只有 hash 不同）。实测文章页 `index=1`，点两个目录锚点后
  `index=3`、`history.length` 由 3 增到 5；此时 `back()` 只退一条，落在上一个锚点
  （正文中间），表现为「点过目录再返回，回到了点目录的位置」。

  **判定依据**：Astro 的客户端路由在 `history.state` 上维护单调递增的 `index`
  （`node_modules/astro/dist/transitions/router.js`：`index: ++currentHistoryIndex`，
  并据此判定 forward/back）。`backButton.ts` 在每次 `astro:page-load` 记下本页的
  `indexAtLoad`，点击返回时按它推算步长：

  | 情况 | 条件 | 行为 |
  | --- | --- | --- |
  | 本页是标签页第一个条目 | `indexAtLoad <= 0` | 无来源页 → 回首页 |
  | 有同页锚点条目 | `hops = indexNow - indexAtLoad + 1 > 1` | `history.go(-hops)` 一次跨过去 |
  | 无锚点跳转 | `hops === 1` | `history.back()`（与修复前等价） |

  `index` 不可用时（例如 View Transitions 被禁用）退回站内路径栈判断，仍能给出合理结果。
  回归断言见 `scripts/check.mjs` 的「返回按钮-目录锚点后返回」（含滚动恢复）。

### 6.4 搜索功能

- **搜索框就在主界面页头**，每个页面都有：输入即出下拉结果，
  命中关键词高亮，回车打开首条结果，↑/↓ 键选择，Esc 关闭
- `/search/` 页面保留，用于移动端图标入口和可分享的搜索链接
  （例如 `/search/?q=Astro`）
- 搜索覆盖标题、标签、摘要和正文；索引在构建时自动生成（`search.json`）

**什么时候该换成 Pagefind**

现在的搜索是「整包下载 `search.json` + `includes` 全串匹配」，索引体积随文章数
线性增长（每篇约 1.7 KB）：

| 文章数 | search.json | gzip 后 |
| --- | --- | --- |
| 24（当前） | 40 KB | 约 11 KB |
| 80 | 134 KB | 约 38 KB |
| 200 | 334 KB | 约 95 KB |

**到 80 篇**时 `npm run build` 会打印一条 `[search]` 开头的提醒（只提醒，不阻断构建），
那就该迁移了。迁移步骤：

1. `npm i -D pagefind`
2. `package.json` 的 build 脚本改成 `astro build && pagefind --site dist`
   （CI 的 `ci.yml` 与部署的 `deploy.yml` 都要同步改）
3. 删掉 `src/pages/search.json.ts`，把 `src/scripts/search.ts` 里的
   `buildIndex()` / `searchIndex()` 换成 Pagefind 的 `pagefind.search()`
4. `Header.astro` 与 `search.astro` 两处调用方跟着改（它们共用 `scripts/search.ts`）
5. 重新跑 `npm run check`——里面有 6 条搜索相关断言会验证这次改动

它的好处是索引分片按需加载、自带中文分词；代价是多一个构建步骤和依赖。

### 6.5 动效

- 内容进入视口时渐显（带错峰延迟）；浏览器开启“减少动态效果”或
  无 JS 时自动降级为直接显示
- 悬停微交互：导航下划线生长、标签上浮、主题图标旋转、列表行高亮
- 全部用原生 CSS 过渡/动画实现，不依赖第三方动画库
- **页面切换动画**：全站启用 View Transitions，点击文章时标题会从列表位置
  平滑“飞”到文章页标题位置（返回时反向飞回），页面切换带淡入淡出

  **数值不是“调手感”，而是按三条判据定的**（`src/styles/effects.css`
  顶部有 `--vt-*` 变量，改一处即全局生效）。判据来自 CDP 逐帧采样真实
  过渡轨迹，而不是看着改：

  | 判据 | 旧版实测 | 现值 | 为什么 |
  | --- | --- | --- | --- |
  | 起步速度 ≈ 0 | **13.4/s**（21ms 内老层从 1.0 掉到 0.718） | **0** | 出场若用 ease-out，起始斜率很大，视觉上就是“啪一下没了” —— 这是“生硬”的根因。改用 ease-in（`cubic-bezier(0.4,0,0.6,1)`，起始斜率 0） |
  | 始终有一层够清晰 | 最亮层仅 **0.40** | **0.78** | 中途两层都不够实在，整页发虚。出场 200ms / 入场 320ms 错开可解 |
  | 不闪暗 | 总亮度最低 **0.79**（塌陷 21%） | **0.98** | 那一刻整页短暂变暗 |
  | 层间空间分离 | 位移仅 7px | **22px** | 两层文字几乎重合时，溶解＝双重曝光。位移把它们错开，观感是“推上去”；再大（>30px）就像整页推拉 |

  **页头/页脚必须显式命名，否则会重影**（这条最隐蔽）：
  `transition:persist` 只保证 **DOM 节点复用**，并不会把元素从快照里摘出去 ——
  实测其 `view-transition-name` 仍是 `none`，于是页头同时出现在 old 和 new
  两张 root 快照里。root 层一旦做位移，页头就被渲染**两份**（各带反向位移）。
  修法是给 `.site-header` / `.site-footer` 显式 `view-transition-name`，
  使其成为独立层并关掉自身动画（内容一致，本就不需要过渡）。

  > 三个容易踩的点：
  > 1. `transition:persist` **只对原生元素生效**，写在 `<Header />` 组件上会被
  >    **静默忽略**（不报错、产物里也没有该属性）。必须写在组件内部的根元素上。
  > 2. **persist 不等于“不进快照”**。见上面页头重影那条 —— 必须额外命名。
  > 3. 不要给 `<main>` 加 `transition:name`。加了会生成独立的
  >    `page-content` 层，它同样是一对新旧快照、同样交叉淡入 ——
  >    等于把重影从 root 挪到这里，白忙一场。

  > 以上判据都固化成了 `npm run check` 里的断言。**这些断言不可省**：
  > 方向性关键帧选择器不匹配、“起步平缓”被改回 ease-out、页头退化成两份 ——
  > 这些情况下**页面照样能正常切换**，只是动效静默劣化，肉眼几乎发现不了。

#### 轴向：左右翻阅 vs 上下翻阅

站内的切换有**两个轴**，必须区分，否则“方向感是错的”：

| 轴 | 场景 | 位移 |
| --- | --- | --- |
| `y`（默认） | 列表 ⇄ 文章、标签页、搜索 | 上下推 |
| `x` | 翻页（← 上一页 / 下一页 → / 页码）、文章底部（更新的 / 更早的文章） | 左右推 |

规则是 **新内容从被点击控件所在的那一侧进来**：

- 点**右侧**控件（下一页 →、更早的文章）→ 内容向左走，新页自**右**入
- 点**左侧**控件（← 上一页、更新的文章）→ 内容向右走，新页自**左**入

实现要点：

1. 控件上标 `data-vt-axis="x"` 与 `data-vt-dir="prev|next"`；由
   `src/scripts/vtAxis.ts` 在 `astro:before-preparation` 时依据
   `event.sourceElement` 把结果写到 `<html>` 上。
2. **不能用 Astro 的 `direction` 判前后**：点「← 上一页」在浏览器历史里是
   一次**前进**导航，Astro 会标成 `forward`，但翻页语义上它必须与
   「下一页」互为镜像。所以 `data-vt-dir` 优先。
3. **后退不是第二套动画，而是前进的逐项取负**（`vt-out-back` 是
   `vt-out-forward` 的镜像）。这样“哪来哪去”由**构造**保证，不靠两处数值
   手动对齐 —— 手动对齐的写法只要改单边数值就会悄悄不对称。
4. 浏览器返回键没有 `sourceElement`，按 URL 形态兜底：两端都是
   `/` 或 `/page/N/` 时判为横向。

#### 字体（具名元素）必须与页面同向同速

标题在列表页与文章页共用一个 `view-transition-name`，会被**抽离** root
快照成为独立层。实测这一层默认拿到 Astro 内建的 `astroFadeOut` /
`astroFadeIn` —— **纯淡化、完全不位移**。于是页面在动、标题文字不动，二者脱节。

这正是“字体移动方向与页面切换不一致”的根源。修法是让具名层的 old/new
也跑**同一组键帧、同一时长**（`effects.css` 里那几段
`html[data-astro-transition=…]::view-transition-old(*)`）。

  **改时长/缓动时**：只动 `effects.css` 顶部的 `--vt-out-dur` / `--vt-in-dur` /
  `--vt-out-ease` / `--vt-in-ease` / `--vt-shift`。注意三条硬约束：
  出场时长必须 **<** 入场时长；出场缓动的 **y1 必须为 0**；位移不要超过 ~30px。

  轴向只由 `--vt-ax` / `--vt-ay` 决定（默认 `0 / 22px`；`html[data-vt-axis='x']`
  时互换）。**键帧只引用这两个变量**，所以整套动画天然“同向同速” ——
  想再改轴向，加一条覆盖 `--vt-a*` 的规则即可，不必碰任何 `@keyframes`。

- 内链悬停即预取（prefetch），点击页面切换几乎即时
- 浏览器返回键遇到路由交换异常时会自动整页刷新兜底，保证页面不空白


### 6.6 首页翻页与滚动条

- 每页文章数由 `src/consts.ts` 的 `PER_PAGE`（当前 6）统一控制，首页与
  `/page/N/` 分页页共用同一个值。**只改这一处**，不要在调用方再写死数字：
  `Archive.astro` 的链接契约（第 1 页 = `/`、第 N 页 = `/page/N/`）要求各页
  perPage 一致，否则总页数、切片范围与上/下一页目标会全面错位
- 分页是**静态页面**（每页一个真实 HTML），无 JS 也能翻页，浏览器后退键天然可用；
  旧书签里的 `?page=N` 由首页内联脚本重定向到 `/page/N/`
- 页面右侧滚动条已定制样式，随深浅主题自动切换

## 9. 发布前的质量检查（可选）

项目里带了两个验证脚本，需要先启动本地服务器（`dev` 或 `preview` 都行）：

```powershell
npm.cmd run dev          # 或 npm.cmd run preview
```

然后另开一个终端，直接用 npm scripts 跑（已注册在 `package.json`）：

```powershell
npm.cmd run check        # 无头浏览器断言：布局、字体、主题、链接、RSS（有 FAIL 时退出码非 0）
npm.cmd run screenshot   # 生成各页面截图到 .shots/
```

不依赖浏览器的两项，可以直接在 CI 或提交前跑：

```powershell
npm.cmd run sync         # 生成内容集合类型（.astro/ 不进版本库，克隆后要先跑）
npm.cmd run typecheck    # TypeScript 类型检查，有错时退出码非 0
npm.cmd run og           # 重新生成每篇文章的分享图到 public/og/
```

> 两个脚本会自己从所在位置推导项目根目录，不再写死盘符路径；Chrome 路径可用
> `CHROME_BIN` 环境变量覆盖（默认 `C:/Program Files/Google/Chrome/Application/chrome.exe`）。
> 如果服务器不在 4321 端口，用 `BASE_URL=http://localhost:端口 npm.cmd run check` 指定。

检查项包括：页面有无横向溢出、字体是否加载、深浅主题是否生效、
导航是否换行、全站链接是否可达、RSS 是否正常。发布前跑一遍更稳妥。

### 订阅源为什么只放最近 30 篇

`rss.xml` 输出的是**全文**（`<content:encoded>`），每篇约 5 KB；而阅读器
**每次轮询都会拉整个 feed**。不设上限的话它会随文章数一直涨：

| 文章数 | rss.xml | gzip 后 |
| --- | --- | --- |
| 28（当前） | 140 KB | 33 KB |
| 100 | 约 500 KB | 115 KB |

所以 `src/pages/rss.xml.js` 里定了 `FEED_LIMIT = 30`，只把**最近 30 篇**放进
订阅流，体积从此恒定。旧文章不会消失——只是不再出现在订阅源里，仍可从站点访问、
仍会进 sitemap 和搜索索引。

改这个数字只影响 `rss.xml`，其他一律不动。

### sitemap 的 lastmod 是怎么来的

`sitemap-0.xml` 里 48 条 URL 有 46 条带 `<lastmod>`，缺的两条是 `/about/` 与
`/search/` —— 它们没有可靠的时间语义，**宁可缺也不给假的**。

日期按页面类型分别取，逻辑都在 `astro.config.mjs` 的 `serialize` 里：

| 页面 | lastmod |
| --- | --- |
| `/posts/<slug>/` | 该篇的 `updated`（没有就用 `date`） |
| `/`、`/page/N/`、`/tags/` | 全站最新一篇的日期 |
| `/tags/<slug>/` | **该标签下**最新一篇的日期 |
| `/about/`、`/search/` | 不输出 |

> 注意日期口径要统一：这里和文章页的「更新于」、RSS 的 `lastBuildDate` 一样，
> 都优先用 `updated`。全文里只有这一处例外——因为配置加载期拿不到
> Content Collections，只能构建期直接读一遍 `src/content/posts/*.md` 的 frontmatter。

### 哪些页面不收录（noindex）

`BaseLayout` 有一个 `noindex` 参数，传了就**输出 `noindex` 且不输出 canonical**：

| 页面 | 原因 |
| --- | --- |
| `/404` | 它的 canonical 原本指向并不存在的 `/404/` —— 等于主动让搜索引擎去收录一个死地址，比不写更糟 |
| `/search/` | 站内搜索是**工具而不是内容**，初始状态下没有独有信息 |

另外 `astro.config.mjs` 的 sitemap `filter` 会把 `/search/` 排除掉 ——
**一边 noindex 一边又放进 sitemap 是自相矛盾的信号**，要做就一起做。
（现在 sitemap 是 47 条。）

新增页面时如果需要 noindex，在 `<BaseLayout>` 上加一个属性即可，
不用去动 head 里的标签。

### 结构化数据（JSON-LD）

全站共 29 个 JSON-LD 块，**全部通过 JSON 校验**：

| 页面 | `@type` | 说明 |
| --- | --- | --- |
| 首页 | `WebSite` + `Person` | 声明站点与作者两个实体 |
| 每篇文章 | `BlogPosting` | 含 `datePublished` / `dateModified` / `keywords` 等 |

首页那份走 `<BaseLayout>` 的 `slot="ld"` 插槽，内容在 `src/pages/index.astro`
的 frontmatter 里定义：

```astro
<script type="application/ld+json" is:inline set:html={JSON.stringify(jsonLd)} slot="ld" />
```

> 两处刻意的取舍：**不放 `email`**（关于页已经写明，没必要再交给爬虫一份结构化
> 联系方式）；`potentialAction` 里的 `SearchAction` 指向 `/search/?q={...}`，
> 它和搜索页实际读取的参数一致 —— 虽然 Google 已经下线了 sitelinks searchbox，
> 但标记本身是准确的，留着给其他消费方用。

改站点名称/作者时，首页这两条会跟着 `consts.ts` 自动变，不用单独改。

> `npm.cmd run check` 结束时会在末尾打印一行汇总（`N passed, M failed`），
> 并在**有 FAIL 时返回非 0 退出码**（全 PASS 返回 0），可直接用于 CI 或脚本化
> 验证。具体哪几条失败看汇总行之前的明细——以前脚本恒返回 0，FAIL 会被忽略。

## 10. 常见问题（FAQ）

### npm 提示"禁止运行脚本" / 找不到 npm 命令

本机 PowerShell 执行策略限制，改用 `npm.cmd`：

```powershell
npm.cmd install
npm.cmd run dev
```

### git 提示"无法识别" / 不是内部或外部命令

Git 已安装到 `D:\Code\.tools\git` 并加入用户 PATH。**新开的终端窗口**即可直接
使用 `git`；如果当前窗口还报错，关掉重开一个终端。验证方法：

```powershell
git --version
```

推送时不需要再输入密码，凭据由已授权的 gh CLI 自动提供。

### 推送时报 502 / 无法访问 GitHub

本机 GitHub 流量会被本地加速工具（steamcommunity_302 等）接管，它的上游
故障时会返回 502。两个解决办法：

```powershell
# 方法一：临时走 Clash 代理推送（推荐，无需动任何工具）
git -c http.proxy=http://127.0.0.1:7897 push

# 方法二：重启 steamcommunity_302 后恢复正常，再直接 git push
```

如果换了代理端口，把命令里的 `7897` 换成实际端口即可。

### 端口被占用，dev 服务器起不来

```powershell
npm.cmd run dev -- --port 3000
```

### 构建报错（比如日期格式）

frontmatter 校验失败。看报错提示，检查 `date` 是否为 `YYYY-MM-DD`、
必填字段是否齐全。改完重新构建即可。

### git 提示 CRLF / LF 警告

Windows 行尾转换的提示，**无害**，不影响任何功能。

### 推送被拒绝：缺少 workflow 权限

首次推送 `.github/workflows/` 目录时需要 workflow 权限。已授权过，
如果以后换新电脑，用 gh CLI 登录后执行：

```powershell
D:\Code\.tools\gh\bin\gh.exe auth refresh -h github.com -s workflow
```

### 改了代码但线上没变化

1. 确认执行了 `git push` 且 Actions 运行是绿色（见 7.2）
2. 浏览器强制刷新（Ctrl+F5），GitHub Pages 有 CDN 缓存
3. 检查是否把 `draft` 写成了 `true`

### 怎么停掉本地预览服务器

在任务管理器里结束对应的 `node` 进程，或关掉运行它的终端窗口。

### 想迁移到 Vercel / Netlify

项目已内置 `vercel.json` 和 `netlify.toml`，把仓库导入对应平台即可，
构建命令 `npm run build`，发布目录 `dist`。
