## 1. 快速开始

```powershell
# 进入项目目录
cd D:\Code\Deepseek\blog

# 安装依赖（只需一次；如果之前装过可跳过）
npm.cmd install

# 本地开发：启动后浏览器打开 http://localhost:4321
npm.cmd run dev

# 构建线上版本（输出到 dist/）
npm.cmd run build

# 预览构建结果
npm.cmd run preview
```

> **本机注意**：PowerShell 默认禁止运行 `npm.ps1` 脚本，所以本机统一用
> `npm.cmd` 而不是 `npm`。如果执行 `npm` 报"禁止运行脚本"，换 `npm.cmd` 即可。

发布到线上只需一条命令组合：

```powershell
git add -A
git commit -m "更新内容"
git push
```

推送后 GitHub Actions 会自动构建并部署，约 1 分钟后线上更新。

## 3. 写文章（最常用）

### 3.1 新建一篇文章

在 `src/content/posts/` 下新建一个 Markdown 文件即可。文件名就是文章的网址
（slug），**只能用英文小写 + 连字符（kebab-case）**，例如 `my-first-post.md`
对应网址 `https://azainl.github.io/posts/my-first-post/`。

文件头部必须写 frontmatter（两行 `---` 之间的内容）：

```md
---
title: "文章标题"
description: "文章摘要，显示在首页列表、搜索引擎和分享卡片里"
date: 2026-08-03
tags: ["随笔", "思考"]
draft: false
---

正文从这里开始，支持标准的 Markdown 语法。
```

### 3.2 frontmatter 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `description` | 是 | 摘要，建议一句话说清文章内容 |
| `date` | 是 | 发布日期，格式 `YYYY-MM-DD` |
| `tags` | 否 | 标签数组；每个标签生成 `/tags/<slug>/` 页面（URL 用英文 slug，映射见 `src/data/tags.ts`） |
| `draft` | 否 | `true` 时文章只在本地可见，不会发布 |
| `updated` | 否 | 修改日期，格式同 `date`，**不能早于 `date`**；填了之后文章页显示「更新于」，并同步到 JSON-LD 的 `dateModified` 与 RSS 的 `lastBuildDate` |
| `featured` | 否 | `true` 时进首页「精选文章」区块（建议最多 3 篇） |

字段缺失或日期格式错误时，构建会直接报错（这是保护机制，防止坏数据上线）。
`draft: true` 与**未来日期**的文章都不会进入线上产物，但本地 `npm run dev`
下仍可见，方便预览定时发布。
标签页会显示每个标签的一句话描述，定义在 `src/data/tags.ts` 里，可自由增改。
新增标签时建议在该文件里补一行 slug，否则 URL 会退化成百分号编码。

> **改了文章标题后记得跑一次 `npm.cmd run og`**，重新生成社交分享卡片图。
> 分享图是预生成并提交进仓库的（构建时不生成，CI 因此不需要 sharp 和中文字体）；
> 漏跑不会报错，只会让这篇文章回退成全站默认图。新增/删除文章同理。

### 3.3 支持的 Markdown 语法

标题、段落、**加粗**、*斜体*、[链接](https://example.com)、
`行内代码`、列表、引用、表格、代码块（带语法高亮）都支持。

```md
## 二级标题

### 三级标题

> 这是引用，会显示成带左边线的样式

- 列表项一
- 列表项二

1. 有序列表一
2. 有序列表二

| 表头一 | 表头二 |
| --- | --- |
| 内容 | 内容 |

    ```js
    console.log('代码块自动高亮');
    ```
```

### 3.4 插入图片

把图片文件放进 `public/images/`（没有就新建），然后在文章里写：

```md
![图片说明](/images/文件名.png)
```

图片会按原样发布（**不经过 Astro 的图片优化管道**），所以体积完全取决于你放进去的源文件。

> **先压再放**：正文图最大显示宽度是 576px（CSS `min(100%, 36rem)`），
> 所以宽 **1152px 就足够覆盖 2x 屏**，再大纯属浪费流量。
> 现有配图统一为 **1152×648 / JPEG q78**。
> 新增图请先压到这个规格再放进 `public/images/`。

**署名要跟图源对上**。题图下面那行斜体是版权行，格式由
`.prose p:has(img) + p:has(em)` 自动套用，但**内容得你自己写准**：

| 图源 | 署名写法 |
| --- | --- |
| 早期几张，来自 Flickr | `*题图来自 Flickr，CC 授权*` |
| 新的图，来自 Unsplash | `*题图来自 Unsplash，摄影 <作者>*` |

> 找图：`loremflickr` 目前返回 401 已不可用，可改用
> `https://picsum.photos/id/<id>/1200/675`（固定 `id` 保证每次同一张）；
> 作者名从 `https://picsum.photos/id/<id>/info` 取。
> **下载后务必打开看一眼**——占位图服务偶尔会返回内容完全不搭的图。

### 3.5 阅读时长

阅读时长是自动计算的（中文按 400 字/分钟估算），无需手动填写。

### 3.6 草稿与预览

把 `draft: true` 的文章推送到 GitHub 不会出现在线上；在本地 `npm.cmd run dev`
时仍然可以看到，方便先写后发。

> **补充：未来日期也是同理。** 如果 `date` 写的是未来的某天（用于定时发布），
> 线上会等到那天才出现这篇文章；但在本地 `npm.cmd run dev` 下能直接预览效果。
> 这套"生产过滤 / 开发可见"的逻辑统一在 `src/utils/posts.ts` 的
> `getPublishedPosts()` 里。

---

### 3.7 重命名或删除文章（要配重定向）

文章一旦发布，URL 就会出现在 RSS、外链、搜索引擎里。**直接改文件名或删文件会让
这些旧链接 404**。正确做法：

1. 改文件名后，在 `astro.config.mjs` 的 `redirects` 里加一条旧路径 → 新路径的映射，
   例如：
   ```js
   redirects: {
     '/posts/旧文件名/': '/posts/新文件名/',
   }
   ```
2. 静态构建会为每个旧路径生成带 `meta refresh` 的重定向页，GitHub Pages /
   Netlify / Vercel 都能用，无需平台额外配置。
3. 删除文章同理——如果这篇文章曾被外链引用，也加一条重定向到首页或同类文章。

> 走 `src/utils/posts.ts` 统一取数的页面（首页、文章页、RSS、搜索、标签页）都会
> 自动跟随文件变化，无需逐个改引用。

## 4. 修改站点信息

所有站点配置集中在 `src/consts.ts`，只改这一个文件即可：

```ts
export const SITE = {
  name: 'Azain',                    // 站点名（页脚等位置显示）
  title: '山月 · 个人博客',          // 浏览器标签页标题
  description: '一个关于代码、阅读与生活的个人博客。', // 站点简介
  author: 'Azain',                  // 作者名（关于页使用）
  email: '2013386765@qq.com',       // 联系邮箱（关于页显示）
  locale: 'zh-CN',
};
```

> **域名只在 `astro.config.mjs` 的 `site` 里配置**：RSS、sitemap、canonical、
> `og:url` 全部由它派生。`consts.ts` 里曾经有一个从不被任何代码引用的 `url`
> 字段，两处配置容易只改一处，已删除。

修改后执行 `npm.cmd run build` 确认没有报错，再 `git push` 发布。

另外两处可选的独立修改：

- 页头左上角的文字（站点标识）：`src/components/Header.astro` 里的
  `Az<span>ain</span>`（**硬编码**，不会随 `consts.ts` 的 `name` 自动变化）。
  如果换了站点名，这里和 `SITE.name`（用于 `aria-label`、页脚、各页 `<title>`）
  要一起改，否则标识和朗读/标题会对不上。
- 站点图标：替换 `public/favicon.svg`；分享预览图替换 `public/og.svg`。

## 5. 修改设计（外观）

全站样式在 `src/styles/` 下，由 `global.css` 作为入口 `@import` 六个分片
（`base` / `header` / `home` / `pages` / `effects` / `post-extras`）。
**@import 的顺序就是层叠顺序，不要调换**。设计令牌在 `base.css` 顶部。
改配色/字体改 `base.css`，改首页排版改 `home.css`，以此类推。

### 5.1 颜色

`:root { }` 是浅色主题的变量，`.dark { }` 是深色主题的变量，两套对应关系一致：

| 变量 | 作用 |
| --- | --- |
| `--bg` | 页面背景色 |
| `--ink` | 正文文字色 |
| `--ink-2` | 次要文字色（摘要、正文说明） |
| `--ink-3` | 弱文字色（日期、年份） |
| `--accent` | 全站强调色（链接、点缀、高亮） |
| `--line` | 分隔线颜色 |
| `--code-bg` | 代码块背景 |

改颜色只需改变量值，全站自动生效。注意保持：**全站只用一个强调色**，
深浅两套都改，避免出现浅色下的强调色在深色下看不清。

### 5.2 字体

字体是**自托管的可变字体**，不依赖外部服务，在 `src/layouts/BaseLayout.astro`
里通过 `@fontsource` 包的 woff2 文件直接引入并内联声明（只取拉丁子集，避免下载
无用字符）：

```ts
// 直接指向具体 woff2 文件，拿到它构建后的 URL
import geistUrl from '@fontsource-variable/geist/files/geist-latin-wght-normal.woff2?url';
import serifUrl from '@fontsource-variable/source-serif-4/files/source-serif-4-latin-wght-normal.woff2?url';
```

然后在同一文件 `<head>` 内：用 `<style is:inline>` 写两段 `@font-face` 声明，并
`<link rel="preload">` 提前加载这两个字体（声明必须和 preload 同处 `<head>`，
否则字体声明晚于预加载，FOIT/FOUT 行为不可控）。

字体栈定义在 `global.css` 的 `--font-sans` / `--font-serif` / `--font-mono`。
想换字体：从 `@fontsource-variable/字体名` 找到对应的 `files/*.woff2?url` 路径，
改 import、改 `@font-face` 的 `font-family` 和 `global.css` 的变量即可。

### 5.3 布局与圆角

- `--container`（文章宽度）和 `--container-wide`（列表页宽度）控制页面宽度
- `--radius` / `--radius-pill` / `--radius-inline` 控制圆角体系，
  保持同一套圆角规则，不要混用
- 首页文章列表、文章页排版分别在 `src/pages/index.astro` 和
  `src/layouts/PostLayout.astro`

### 5.4 深浅主题

- 首次访问跟随系统偏好，之后记住手动选择（存在浏览器 localStorage）
- 主题初始化脚本在 `BaseLayout.astro` 的 `<head>` 里，切换按钮在
  `Header.astro`
- 新增配色时记得同时写 `:root` 和 `.dark` 两套

## 6. 页面与路由

### 6.1 现有路由

| 路径 | 来源 | 说明 |
| --- | --- | --- |
| `/` | `src/pages/index.astro` | 首页（第 1 页），按年份分组 + 每页 6 篇 |
| `/page/N/` | `src/pages/page/[page].astro` | 第 2 页起的静态分页页；旧链接 `?page=N` 会重定向到这里 |
| `/posts/<slug>/` | 自动生成 | 每篇文章一个详情页 |
| `/tags/` | `src/pages/tags/index.astro` | 全部标签 |
| `/tags/<slug>/` | 自动生成 | 某标签下的文章（英文 slug，如 `/tags/frontend/`） |
| `/search/` | `src/pages/search.astro` | 搜索页（移动端入口与分享链接用） |
| `/about/` | `src/pages/about.astro` | 关于页 |
| `/rss.xml` | 自动生成 | RSS 订阅源（**全文输出，只保留最近 30 篇**，见下） |
| `/sitemap-index.xml` | 自动生成 | 搜索引擎用的站点地图 |
| `/404` | `src/pages/404.astro` | 页面不存在时 |

### 6.2 新增一个页面

在 `src/pages/` 下新建 `xxx.astro`，套用基础模板：

```astro
---

---

<BaseLayout title="页面标题" description="页面描述">
  <div class="page-head">
    <h1>页面标题</h1>
    <p>页面说明文字。</p>
  </div>
  <div class="container">
    页面内容……
  </div>
</BaseLayout>
```

保存后访问 `/xxx/`（文件名即路径）。

### 6.3 修改导航和页脚

- 导航链接：`src/components/Header.astro` 里的 `links` 数组
- 页脚内容：`src/components/Footer.astro`
- **文章标题上方的返回按钮**：在文章页标题（`post-header`）上方显示，不占用顶部栏。
  点击走 `history.back()` 返回上一页；无站内历史（例如直接输入文章地址）时回到首页。
  返回使用站内浏览器历史 + View Transitions（带动画、不整页刷新），并恢复到进入前页面的滚动位置。
  实现见 `src/scripts/backButton.ts`（导航栈与返回逻辑）。

### 6.4 搜索功能

- **搜索框就在主界面页头**，每个页面都有：输入即出下拉结果，
  命中关键词高亮，回车打开首条结果，↑/↓ 键选择，Esc 关闭
- `/search/` 页面保留，用于移动端图标入口和可分享的搜索链接
  （例如 `/search/?q=Astro`）
- 搜索覆盖标题、标签、摘要和正文；索引在构建时自动生成（`search.json`）

**什么时候该换成 Pagefind**

现在的搜索是「整包下载 `search.json` + `includes` 全串匹配」，索引体积随文章数
线性增长（每篇约 1.7 KB）：

| 文章数 | search.json | gzip 后 |
| --- | --- | --- |
| 24（当前） | 40 KB | 约 11 KB |
| 80 | 134 KB | 约 38 KB |
| 200 | 334 KB | 约 95 KB |

**到 80 篇**时 `npm run build` 会打印一条 `[search]` 开头的提醒（只提醒，不阻断构建），
那就该迁移了。迁移步骤：

1. `npm i -D pagefind`
2. `package.json` 的 build 脚本改成 `astro build && pagefind --site dist`
   （CI 的 `ci.yml` 与部署的 `deploy.yml` 都要同步改）
3. 删掉 `src/pages/search.json.ts`，把 `src/scripts/search.ts` 里的
   `buildIndex()` / `searchIndex()` 换成 Pagefind 的 `pagefind.search()`
4. `Header.astro` 与 `search.astro` 两处调用方跟着改（它们共用 `scripts/search.ts`）
5. 重新跑 `npm run check`——里面有 6 条搜索相关断言会验证这次改动

它的好处是索引分片按需加载、自带中文分词；代价是多一个构建步骤和依赖。

### 6.5 动效

- 内容进入视口时渐显（带错峰延迟）；浏览器开启"减少动态效果"或
  无 JS 时自动降级为直接显示
- 悬停微交互：导航下划线生长、标签上浮、主题图标旋转、列表行高亮
- 全部用原生 CSS 过渡/动画实现，不依赖第三方动画库
- **页面切换动画**：全站启用 View Transitions，点击文章时标题会从列表位置
  平滑"飞"到文章页标题位置（返回时反向飞回），页面切换带淡入淡出
- 内链悬停即预取（prefetch），点击页面切换几乎即时
- 浏览器返回键遇到路由交换异常时会自动整页刷新兜底，保证页面不空白

### 6.6 首页翻页与滚动条

- 每页文章数由 `src/consts.ts` 的 `PER_PAGE`（当前 6）统一控制，首页与
  `/page/N/` 分页页共用同一个值。**只改这一处**，不要在调用方再写死数字：
  `Archive.astro` 的链接契约（第 1 页 = `/`、第 N 页 = `/page/N/`）要求各页
  perPage 一致，否则总页数、切片范围与上/下一页目标会全面错位
- 分页是**静态页面**（每页一个真实 HTML），无 JS 也能翻页，浏览器后退键天然可用；
  旧书签里的 `?page=N` 由首页内联脚本重定向到 `/page/N/`
- 页面右侧滚动条已定制样式，随深浅主题自动切换

## 9. 发布前的质量检查（可选）

项目里带了两个验证脚本，需要先启动本地服务器（`dev` 或 `preview` 都行）：

```powershell
npm.cmd run dev          # 或 npm.cmd run preview
```

然后另开一个终端，直接用 npm scripts 跑（已注册在 `package.json`）：

```powershell
npm.cmd run check        # 无头浏览器断言：布局、字体、主题、链接、RSS（有 FAIL 时退出码非 0）
npm.cmd run screenshot   # 生成各页面截图到 .shots/
```

不依赖浏览器的两项，可以直接在 CI 或提交前跑：

```powershell
npm.cmd run sync         # 生成内容集合类型（.astro/ 不进版本库，克隆后要先跑）
npm.cmd run typecheck    # TypeScript 类型检查，有错时退出码非 0
npm.cmd run og           # 重新生成每篇文章的分享图到 public/og/
```

> 两个脚本会自己从所在位置推导项目根目录，不再写死盘符路径；Chrome 路径可用
> `CHROME_BIN` 环境变量覆盖（默认 `C:/Program Files/Google/Chrome/Application/chrome.exe`）。
> 如果服务器不在 4321 端口，用 `BASE_URL=http://localhost:端口 npm.cmd run check` 指定。

检查项包括：页面有无横向溢出、字体是否加载、深浅主题是否生效、
导航是否换行、全站链接是否可达、RSS 是否正常。发布前跑一遍更稳妥。

### 订阅源为什么只放最近 30 篇

`rss.xml` 输出的是**全文**（`<content:encoded>`），每篇约 5 KB；而阅读器
**每次轮询都会拉整个 feed**。不设上限的话它会随文章数一直涨：

| 文章数 | rss.xml | gzip 后 |
| --- | --- | --- |
| 28（当前） | 140 KB | 33 KB |
| 100 | 约 500 KB | 115 KB |

所以 `src/pages/rss.xml.js` 里定了 `FEED_LIMIT = 30`，只把**最近 30 篇**放进
订阅流，体积从此恒定。旧文章不会消失——只是不再出现在订阅源里，仍可从站点访问、
仍会进 sitemap 和搜索索引。

改这个数字只影响 `rss.xml`，其他一律不动。

### sitemap 的 lastmod 是怎么来的

`sitemap-0.xml` 里 48 条 URL 有 46 条带 `<lastmod>`，缺的两条是 `/about/` 与
`/search/` —— 它们没有可靠的时间语义，**宁可缺也不给假的**。

日期按页面类型分别取，逻辑都在 `astro.config.mjs` 的 `serialize` 里：

| 页面 | lastmod |
| --- | --- |
| `/posts/<slug>/` | 该篇的 `updated`（没有就用 `date`） |
| `/`、`/page/N/`、`/tags/` | 全站最新一篇的日期 |
| `/tags/<slug>/` | **该标签下**最新一篇的日期 |
| `/about/`、`/search/` | 不输出 |

> 注意日期口径要统一：这里和文章页的「更新于」、RSS 的 `lastBuildDate` 一样，
> 都优先用 `updated`。全文里只有这一处例外——因为配置加载期拿不到
> Content Collections，只能构建期直接读一遍 `src/content/posts/*.md` 的 frontmatter。

> `npm.cmd run check` 结束时会在末尾打印一行汇总（`N passed, M failed`），
> 并在**有 FAIL 时返回非 0 退出码**（全 PASS 返回 0），可直接用于 CI 或脚本化
> 验证。具体哪几条失败看汇总行之前的明细——以前脚本恒返回 0，FAIL 会被忽略。

## 10. 常见问题（FAQ）

### npm 提示"禁止运行脚本" / 找不到 npm 命令

本机 PowerShell 执行策略限制，改用 `npm.cmd`：

```powershell
npm.cmd install
npm.cmd run dev
```

### git 提示"无法识别" / 不是内部或外部命令

Git 已安装到 `D:\Code\.tools\git` 并加入用户 PATH。**新开的终端窗口**即可直接
使用 `git`；如果当前窗口还报错，关掉重开一个终端。验证方法：

```powershell
git --version
```

推送时不需要再输入密码，凭据由已授权的 gh CLI 自动提供。

### 推送时报 502 / 无法访问 GitHub

本机 GitHub 流量会被本地加速工具（steamcommunity_302 等）接管，它的上游
故障时会返回 502。两个解决办法：

```powershell
# 方法一：临时走 Clash 代理推送（推荐，无需动任何工具）
git -c http.proxy=http://127.0.0.1:7897 push

# 方法二：重启 steamcommunity_302 后恢复正常，再直接 git push
```

如果换了代理端口，把命令里的 `7897` 换成实际端口即可。

### 端口被占用，dev 服务器起不来

```powershell
npm.cmd run dev -- --port 3000
```

### 构建报错（比如日期格式）

frontmatter 校验失败。看报错提示，检查 `date` 是否为 `YYYY-MM-DD`、
必填字段是否齐全。改完重新构建即可。

### git 提示 CRLF / LF 警告

Windows 行尾转换的提示，**无害**，不影响任何功能。

### 推送被拒绝：缺少 workflow 权限

首次推送 `.github/workflows/` 目录时需要 workflow 权限。已授权过，
如果以后换新电脑，用 gh CLI 登录后执行：

```powershell
D:\Code\.tools\gh\bin\gh.exe auth refresh -h github.com -s workflow
```

### 改了代码但线上没变化

1. 确认执行了 `git push` 且 Actions 运行是绿色（见 7.2）
2. 浏览器强制刷新（Ctrl+F5），GitHub Pages 有 CDN 缓存
3. 检查是否把 `draft` 写成了 `true`

### 怎么停掉本地预览服务器

在任务管理器里结束对应的 `node` 进程，或关掉运行它的终端窗口。

### 想迁移到 Vercel / Netlify

项目已内置 `vercel.json` 和 `netlify.toml`，把仓库导入对应平台即可，
构建命令 `npm run build`，发布目录 `dist`。
