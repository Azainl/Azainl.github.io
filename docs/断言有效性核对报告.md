# 断言有效性核对报告（2026-11-18）

> 对象：`scripts/check.mjs` 的 **503 条**浏览器断言（4905 行 / 224 KB）
> 方法：源码静态扫描 + 全量运行输出比对 + 故障注入抽样验证
> 结论：**没有发现无效断言**；完成 1 处合并精简，节省 **约 75 秒**（每次运行）

---

## 1. 核对方法

| 手段 | 说明 | 能发现什么 |
|---|---|---|
| 静态扫描 | 解析全部 `check(name, ok, detail)` 调用，提取 `ok` 表达式 | 恒真条件、弱判定、缺参 |
| 输出比对 | 两次全量运行，逐条 diff 断言名 | 行为漂移、重复、遗漏 |
| 故障注入 | 人为破坏产物，确认断言转红 | 「永远为真」的假断言 |

## 2. 逐类核对结果

### 2.1 检查调用完整性 —— ✅ 通过

- `check(` 出现 **393 处**源码调用，运行时展开为 **503 条**（差额来自参数化循环：断点 × 页面 × 视口）。
- **缺参：0 条**。所有调用都传了 `ok` 表达式，没有「只写名字不写条件」的空壳。

### 2.2 恒真断言 —— ⚠️ 2 条，均为**有意的条件跳过**

| 位置 | 断言 | 判定 |
|---|---|---|
| L551 | `翻页边界-末页: 仅一页，跳过` | ✅ 在 `else` 分支，站点只有一页时跳过末页检查。**语义正确** |
| L1425 | `T-26 JSON Feed 可被 JSON.parse` | ✅ 与上方 `catch` 里的 `false` 构成二选一。解析失败会走 false 分支 |

> 两条都不是「假装通过」，而是**显式表达「此场景不适用」**。保留。

### 2.3 弱判定（`!!x` / `!== undefined`）—— ✅ 8 条，均有实际失败可能


全部是「某个可选值是否存在」，值缺失即为失败。**不是弱断言。**

### 2.4 重复断言 —— ✅ 均为「不同条件下重复同一检查」，不可合并

归一化后（数字、断点、页码替换为占位符）出现 12 组重复，逐个查证：

| 重复项 | 次数 | 实际是 | 能否合并 |
|---|---|---|---|
| `Npx 搜索档位` 系列 | 5 | 1024/900/820/768/700 **五个断点**各测一次 | ❌ 合并=丢失响应式覆盖 |
| `文章页收尾行 @N` 系列 | 4 | 390/768/1280/1440 **四个视口** | ❌ 同上 |
| `无横向溢出` | 7 | 首页/文章页/标签页等**不同页面** | ❌ 同上 |
| `深色主题生效` | 4 | 不同页面的深浅两态 | ❌ 同上 |

**结论：无冗余断言。** 这些重复是响应式站点的必要成本。

### 2.5 通用守卫 —— 69 条 `无控制台错误`（占 13.7%）

`runPage()` 每开一个页面自动追加一条。62 次调用 → 68 个 label → 69 条。

> **价值判断**：保留。它抓的是「页面能渲染但脚本报错」——肉眼看不出、只影响部分用户的典型缺陷。
> 但它是每条都新开页面的**主要成本来源**，优化见 §3。

## 3. 合并精简（已实施）

### 3.1 做了什么

`runPage()` 原本每次执行：

```
navigate(url) → sleep 1200ms → localStorage.clear() + location.reload() → sleep 1200ms
```

reload 的唯一目的是清掉上个用例写入的**显式主题偏好**。但 `runPage` 每次都新开标签页，
只要在**首次导航前**注入清除脚本，页面一开始就是干净的：

```
addScriptToEvaluateOnNewDocument(clear) → navigate(url) → sleep 1200ms
```

### 3.2 收益

| | 优化前 | 优化后 |
|---|---|---|
| 每次 runPage 固定等待 | 2400 ms | 1200 ms |
| 62 次合计 | 148.8 s | 74.4 s |
| **节省** | | **约 74 秒** |
| 断言条数 | 503 | 503（不变） |
| 断言名 | — | **逐条完全一致** |

### 3.3 验证

- 全量运行：**503 passed, 0 failed**，断言名与优化前逐行 diff 一致。
- **故障注入**：把 clear 脚本换成空实现 → 3 条主题断言精确转红：
  - `主题-首屏跟随系统: 跟随系统不写 localStorage (dark)`
  - `主题-首屏跟随系统: 未选择时跟随系统换色 (dark)`
  - `主题-首屏跟随系统: 自动跟随仍不写 localStorage (dark)`
  - 恢复后回到 503/503。

> 这证明：清逻辑确实必要，优化没有让测试变松。

## 6. 结论

1. **没有发现无效断言**。393 处调用、503 条运行条目，全部具备真实失败可能。
2. **没有发现冗余断言**。归一化后的 12 组「重复」全部是不同断点/页面/视口的必要覆盖。
3. **完成 1 处精简**：消除 `runPage` 中多余的 reload，节省约 74 秒/次运行，语义零变化。
4. 断言体系是健康的。真正的下一层优化不在「减断言」，而在 T-48「拆文件」与减少重复页面访问。
