## P1-1 🟢 系列 / 专栏

- **问题**：站上有 7 篇天然成系列的文章（「从零搭建博客」起的一组 Astro 主题），但站上没有任何机制表达「这 7 篇是一个系列、按这个顺序读」。读者只能靠标签页把同标签文章混在一起看。
- **排查**：标签页（`/tags/<tag>/`）是**按日期倒序**的平铺列表，无法表达「阅读顺序」。而系列的核心语义恰恰是**顺序**——日期顺序 ≠ 阅读顺序（哪篇该先读是作者定的）。

- **措施**：

  1. **schema 扩展**（`src/content.config.ts`）：
     ```
     series: z.string().optional()
     seriesOrder: z.number().int().positive().optional()
     ```
     并用 `.refine(data => data.seriesOrder === undefined || data.series !== undefined, …)` 强制两者同现 —— **只写序号不写系列名不会生效**，因为单看序号无从知道属于哪个系列。
  2. **系列元数据**（新建 `src/data/series.ts`，51 行）：`SeriesMeta { name, slug, description }` + `SERIES` 数组 + 三个查询函数 `seriesSlug / seriesName / seriesDescription`（含未收录兜底：小写 + 空格转连字符）。
  3. **系列工具**（新建 `src/utils/series.ts`，138 行）：
     - `getSeriesPosts(posts, name)` —— 取某系列的全部文章；
     - `getUsedSeries(posts): Map<string, Post[]>` —— 全站被用到的系列，按各系列首篇日期倒序；
     - `checkSeries(posts): SeriesIssue[]` —— 检查三类问题：`duplicate-order`（序号重复）、`missing-order`（漏号）、`single-member`（系列只有一篇）；
     - `getSeriesContext(posts, current): SeriesContext | null` —— 返回 `{ name, posts, position, total, previous, next }`；**无 series 字段返回 null**（这就是向后兼容的关键开关）。
     - 排序常量 `NO_ORDER = Number.MAX_SAFE_INTEGER`，`orderOf(post)` 缺序号的文章排到最后。
  4. **frontmatter**：7 篇文章加 `series: "Astro 博客实践"` + `seriesOrder: 1..7`（插在 `tags:` 行之后，**正文未动**）。
  5. **文章页**（`src/pages/posts/[slug].astro` + `src/layouts/PostLayout.astro`）：
     - 标题上方一行系列条：`本系列共 N 篇 · 第 k 篇 <系列名链接>`；
     - 页脚加入**系列内导航**，与全站的「上一篇 / 下一篇」**分开显示**——若混在一起，读者会以为「上一篇」就是系列上一篇，实际可能跳到系列外文章；
     - `BlogPosting` 里的 `isPartOf` 指向 `CreativeWorkSeries`；
     - 面包屑变为 首页 → 系列页 → 首个标签 → 标题。
  6. **系列页**（新建 `src/pages/series/[name].astro`，105 行）：结构照抄标签页，但列表行左侧显示**两位阅读序号**（`01`、`02`、…）**而不是日期**；JSON-LD 为 `CollectionPage` + `BreadcrumbList`。
  7. **图标**：新建 `src/icons/stack.svg`（从 `@phosphor-icons/core` 原样复制）。
  8. **样式**（`src/styles/pages.css`）：系列条用**左侧竖线**（`border-left: 2px solid var(--accent)`）而**不是圆角胶囊** —— 胶囊会和已有的 `.tag` 抢同一层视觉语言。
  9. **sitemap**（`astro.config.mjs`）：`readSeriesSlugs()` 正则解析 `src/data/series.ts`，给 `/series/<slug>/` 提供 lastmod。

- **结果/验收**：✅ 7 篇入系列；系列页 `/series/astro-blog/` 渲染 7 行、行首 01–07；文章页系列条与系列内导航均正确；**第 1 篇无「系列上一篇」、第 7 篇无「系列下一篇」**（边界对拍已断言）。

## P1-2 🟢 归档页 `/archive/`

- **问题**：首页既是门面又是归档，但只显示第 1 页（`PER_PAGE = 6`）；想「看全部 32 篇」只能一页页翻。旧报告早就建议单独做归档页，一直未实现。
- **措施**（新建 `src/pages/archive.astro`，161 行）：
  - **按年 → 月分组**（年份降序、月份降序），每组一个 `<h2>` / `<h3>` 标签；
  - **顶部年份胶囊**（`2026 32`）作页内锚点 `href="#year-2026"`；
  - **一行统计**：共 32 篇，约 1.4 万字，跨 1 年、12 个标签（字数按正文汉字数粗算，与 `readingTime` 同口径，故标"约"）；
  - JSON-LD = `CollectionPage` + `BreadcrumbList`（首页 → 归档）；
  - 加入 sitemap；
  - 列表行左侧显示 **`08 日`**（日），因为年月已经由分组标题给出，行内再重复年月是噪音；
  - 页尾输出 `<script type="application/json" id="archive-slugs">` —— 供断言与首页/搜索索引**对拍**。

- **结果/验收**：✅ `/archive/` 渲染 32 行、1 个年份组、4 个月份分隔线、年份锚点与跳转链接双向齐全；**404 页不出现归档列表**（守住既有断言）。

## P1-3 🟢 文章修订记录

- **问题**：`updated` 字段**已经在用**（sitemap 的 lastmod、JSON-LD 的 `dateModified`、RSS 都读它），但**文章页从不显示**。读者看到的是「首次发布」的日期，一篇改过很多次的文章和一成不变的文章看起来一样。
- **措施**（`src/layouts/PostLayout.astro`）：文章页页脚输出 `<p class="post-revision">`，含「首次发布 <日期>」；`isRevised`（`lastModified(post) > post.data.date`）为真时**再补一段**「最后修订 <日期>」。
- **为什么先做这一项**：规划 §4.3 明确「建议从『文章修订记录』开始 —— 改动最小、立刻可见」；数据早已在管线里，只是缺一个渲染出口。
- **结果/验收**：✅ 实测输出 `<p class="post-revision"><span>首次发布<time datetime="2026-07-12T00:00:00.000Z">2026年7月12日</time></span></p>`。

## 回归防线：24 条新断言 + 故障注入

- **理念**（写在 `check.mjs` 新块注释里）：这三项都是**派生视图**——数据来自 frontmatter 与文章集合，页面本身不持有内容。派生视图最典型的退化是**悄悄少一篇或顺序错乱**：页面照样打得开、样式也正常，只有把集合逐一对拍才看得见。**所以全部用对拍，不用「存在性」糊过去。**

- **位置**：`scripts/check.mjs`，标题 `// ---- 归档页 / 系列页 / 修订记录（P1 新增功能）----`，插在既有 `渐进增强兜底` 块之前。

| 组 | 条数 | 关键断言 |
|---|---|---|
| 归档页 | 6 | 与 `/search.json` **双向对拍**（missing/extra）；行数 === 清单长度；年份锚点 ↔ 跳转链接双向 |
| 系列页 | 7 | **行首必须是两位阅读序号而非日期**；JSON-LD 的 `numberOfItems` === 行数 |
| 文章页系列上下文 | 9 | 第 1 篇无上 / 第 7 篇无下（**边界**）；`isPartOf` 指向 `CreativeWorkSeries`；面包屑含系列级 |
| 修订记录 | 2 | 渲染 `post-revision`；含「首次发布」+ `<time datetime=…` |

- **另有 2 处既有断言必须同步上调**（否则新页面可以绕开闸门）：
  1. `safeJsonLd` 调用点下限 `>= 5` → **`>= 7`**（新增归档页、系列页两个调用点）；
  2. JSON-LD 转义段的遍历数组加上 `/archive/`、`/series/astro-blog/`。

  > 这条是**闸门，不是描述**：每新增一个产出 JSON-LD 的页面，下限必须同步上调，否则新页面用裸 `JSON.stringify` 不会被发现。

- **故障注入验证（证明新断言有牙，随后全部恢复）**：向 `dist/` 产物注入 4 处故障 ——
  1. 归档页删一行 `<li class="post-row">`（32→31）→ FAIL「归档页列表行数与清单一致」；
  2. 系列页把 `>01</time>` 改成 `>99</time>` → FAIL「系列页用两位阅读序号而非日期」；
  3. 文章页把「系列下一篇」改成「下一篇」→ FAIL「系列第一篇有【系列下一篇】」；
  4. 删掉 `<p class="post-revision">` → FAIL ×2。

  结果：**234 passed, 5 failed, 239 total**，5 个 FAIL **精确对应**注入点。恢复后重跑 → **239 passed, 0 failed**。
