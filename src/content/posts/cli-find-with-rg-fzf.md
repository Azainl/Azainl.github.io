代码多了、笔记多了之后，最频繁的动作不是"写"，而是"找"。找一个函数定义在哪、一段文案之前怎么写的、哪个文件里还留着 `TODO`。这个需求我几乎全交给 ripgrep（rg）和 fzf。

## ripgrep：默认就聪明的搜索

`rg` 比传统的 `grep` 省心的地方在于，它默认就尊重 `.gitignore`、默认递归、默认高亮，不需要记一堆参数就能用：

```powershell
rg "formatDate"        # 在整个仓库里找包含 formatDate 的行
rg -n "formatDate"     # 顺便带上行号，方便跳转
rg -i "formatdate"     # 大小写不敏感
```

按类型过滤也很顺手，不用自己拼文件后缀：

```powershell
rg "vtName" --type astro   # 只在 .astro 文件里找
rg "TODO" --type md        # 只在 Markdown 笔记里找
```

`-l` 只列文件名，配合别的命令正好：

```powershell
rg -l "readingTime"        # 列出所有用到阅读时长函数的文件
```

## fzf：把结果变成可挑选的列表

`rg` 给出一堆结果，`fzf` 负责让你用模糊搜索在结果里挑。最常用的是从历史里捞命令：

```powershell
# Ctrl-R 调出历史，输入关键字模糊过滤，回车即执行
```

找文件也一样：

```powershell
rg --files | fzf           # 列出所有被追踪的文件，模糊挑一个
```

我给 `rg --files | fzf` 绑了一个短别名，想开某个文件时就敲一下，比在文件树里一层层点快太多。

## 两者连起来

真正好用的是把 `rg` 的匹配结果直接喂给 `fzf`，在"内容匹配"里挑选并跳转：

```powershell
rg "initReadingProgress" -n | fzf
```

选中的那一行带着文件名和行号，复制到编辑器里就能直接定位。这种"先按内容搜，再在结果里挑"的节奏，比记住文件路径靠谱得多——人本来就不擅长记路径。

## 一个原则

> 找东西的成本越低，你就越敢把东西拆细、放散。

当检索几乎零成本时，我反而更愿意把笔记拆成小文件、把函数拆小，因为知道以后随时能找回来。工具的好，常常体现在它悄悄改变了你组织信息的方式。

这两个工具都进了我的 `dotfiles`，换机器拉下来就有。如果你还在用图形界面全局搜索，值得花十分钟试试这组合。
